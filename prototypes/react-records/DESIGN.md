# 計器盤（方向性A）— PC用Web画面のデザイン

## 何のための画面か

最初の画面の役目は、QR付きの複数メーターを巡回した点検について、受信・読み取り・DB記録まで全部そろったかを確かめ、抜けや要確認に対処することです。使うのは、工場で点検する人と、記録を確認する人です。

- 点検ごとに、ルートの各メーターが「撮影→PCに到着→読み取り→記録」のどこまで進んだかを並べる。
- 各メーターの結果を小さな文字盤の絵で見せる。数字を読まなくても、外れたメーターが目に入るようにする。
- 最優先は視認性（ユーザーの追加条件「現場で見やすいように」）。飾りは、情報を読む邪魔にならない量にとどめる。

見本: 開発サーバーで `/#gauge`（点検の一覧）と `/#gauge/I-MULTI-20261112`（1件の点検の詳細）。既存の「機器」画面は `/` のまま。

## 色

ライト基調。計器盤の明るい灰色の面に、文字盤の白のカードを置き、数字は記録計の紺のインクで書く。状態の色は、メーターの目盛りの色分け（緑・黄・赤）にそろえる。

## 文字

書体は BIZ UDPゴシック（Windows 10以降に標準搭載）。外部のフォント配信は使わない。

- 数値: 同じ書体に `font-variant-numeric: tabular-nums` を付け、桁の幅をそろえる（クラス `g-num`）。最初は等幅の BIZ UDゴシックを試したが、小数点の前後が半角1文字分空いて「36. 8」と読めたため、プロポーショナル版にそろえた。

## 余白・角丸・線

- 余白は4pxの倍数: 4・8・12・16・20・24・32。カードの内側は左右20px・上下16px、カード同士の間は12〜16px。
- 角丸は小さくする（機械の銘板に合わせる）: 3px（小）・4px（入力・札）・6px（カード）。
- 線: 区切りは細罫1px、入力枠は罫1px、見出しの下は紺インク2px＋目盛りの定規（12pxごとの小目盛り、60pxごとの大目盛り）。
- 横幅は最大1760px。1366pxでは詳細のカードが3列、1920pxでは4列になる（`minmax(400px, 1fr)`）。

## 文字盤の絵（目玉）

`src/gauge/Dial.tsx`。SVGで、viewBox は 120×112。詳細のカードでは148px、一覧では52px（ミニ）。

- 目盛り: 240°（左下から右下まで、上を通る）。詳細は31本（5本ごとに長い大目盛り）、ミニは6本の大目盛りだけ。色は紺インク。
- 許容範囲の帯: 半径43、太さ8（ミニは12）で、許容の下限から上限まで。色は帯 `#3E8A5C`。許容の外には何も塗らない（緑の帯から針が外れていれば、それが「外れ」と読める）。
- 針: 読み取り値の位置。紺インク、太さ3（ミニは5.5）で、文字盤色の縁を付ける。目盛りの外の値は端を4%越えた所で止める（本物の計器の振り切れと同じ見え方）。中心の軸は紺の丸。
- 目盛りの両端の数字（最小・最大）: 詳細だけ、針があるときだけ。
- 状態の印: 下の切れ目の中央に ● ▲ ■ ◌ を置く。ミニでも形で見分けられる大きさ（約13px）にした。
- 失敗（値なし）: 針を描かず、軸は白抜き。面に赤錆の斜線を敷き、中心の下に「読めず」と書く。
- 未撮影: 外周を紺の破線にし、目盛りを罫の色に落とし、帯と軸を描かない。中央に「未撮影」と書く。
- 途中: 目盛りと帯は描き、針は描かない。軸は白抜きで、中心の下に「待ち」と書く。
- 読み上げ: `role="img"` と `aria-label`（例:「No.3 SYN-002 冷却水 出口圧力。要確認。読み取り値 36.75 kPa、許容 20.0〜35.0 kPa」）。

## 画面の構成

### 点検の一覧（`#gauge`）

1行が1件の点検。新しい順。上の切り替えで「すべて」と「対処が必要」を選ぶ。

```
[日付/時刻] [点検名 / ルート・担当 / 注意の札]   [ミニ文字盤×ルートの台数 | ルート外]   [撮影 4/5台 / 記録 5/5件]   [受信状態]  >
```

- 注意の札: 未撮影N・失敗N・要確認N・ルート外N（あるものだけ）。
- 受信状態: 「受信 完了」（正常の札）、「不足あり N枚未着」（要確認の札）、「受信中 到着/撮影」（途中の札）。
- 行全体が詳細へのリンク。

### 1件の点検の詳細（`#gauge/<点検ID>`）

上から順に並べる。

1. 戻るリンク、点検名＋受信状態、点検ID・ルート・担当・日時・写真の枚数。
2. 全体の進み具合: 撮影→PCに到着→読み取り→記録 の件数（例: 5/6件）。
3. 対処が必要なこと: 未撮影（撮り忘れ）・PCに未着・失敗・要確認・ルート外を、それぞれ1枚の注意枠にまとめる。機器名と、次にする操作（例:「現場で撮り直すか、撮れなかった理由を残してください。」）を書く。
4. ルートの機器のカード（ルート順。切り替えで「要確認を上に」）。カードには、No.・機器ID・機器名・状態の札・文字盤・読み取り値・許容範囲・要確認の理由・4段の進み具合・出所・撮影時刻を載せる。
5. ルート外の機器のカード（別の見出しで分ける）。

出所の言葉: スマホのQR／一覧から／手入力／PCの画像QR（2つ以上は「・」でつなぐ）。

## 歯車・計器の意匠

使う所（3か所だけ）:
- 左上の印（紺の四角に歯車のアイコン1つ）。
- 見出しの下の目盛りの定規。
- 文字盤の絵（情報そのもの）。

禁止:
- 歯車を回す、背景に歯車や計器の模様を敷く、カードの角に飾りの歯車を置く。
- 文字盤の絵を飾りとして使う（必ず実際の値と許容範囲を表す）。
- 金属の質感、影の重ね、光彩、グラデーション、紫系の色、絵文字のアイコン、大文字の英語ラベルの字間を広げた見出し、中央揃えの多用。

## 動き

- 針: 値が変わったときだけ、400msで新しい位置へ回す（`cubic-bezier(.2,.7,.2,1)`）。表示したときの振り上げはしない。
- 進み具合の段: 段が進んだときに、200msで色を変える。
- 点滅・脈打つ動き・読み込みの飾りは使わない。
- `prefers-reduced-motion: reduce` のときは、すべての transition と animation を止める。

## 現場で見やすくする工夫

| 工夫 | 理由 |
|---|---|
| 状態を色・文字・形の3つで示す | 色覚の多様性への配慮と、灰色の印刷や低品質なモニターでも区別できるようにするため |
| 問題は塗り、正常は控えめにする | 一覧で問題のある行だけが目に入るようにするため |
| 左端の帯の太さと模様を状態で変える（細線・縞・塗り・破線） | 離れた所から、行の左端だけで状態が分かるようにするため |
| 文字盤の絵で許容範囲と針を見せる | 数字を読まなくても、外れた計器が目に入るようにするため |
| 読み取り値を44pxの太字にする | 離れた所からも読めるようにするため |
| 本文の最小を16pxにする | 作業着のまま、少し離れて画面を見る使い方を想定したため |
| 数字の桁幅をそろえる | 並んだ値を見比べるときに、桁の位置がずれないようにするため |
| 押せる所の高さを44pxにする（切り替え・戻る） | 手袋のままタッチパネルで操作する場合にも押しやすくするため |
| 撮り忘れのカードを破線で囲み、「未撮影」を3か所に書く | 「何もない」ことは見落としやすいので、形を変えて目立たせるため |
| 注意枠に、次にする操作を書く | 何が起きたかだけでなく、どう直すかまで分かるようにするため |
| 点滅や脈打つ動きを使わない | 長く見続ける画面で目が疲れないようにするため |

- `src/gauge/gauge.css` はこの画面だけで読み込む。`index.css` の要素への指定（`p`・`h1`・`header` など）は層の外にあって強いので、`.gauge` の中では `all: revert-layer` で打ち消している。
- 画面を切り替えると CSS が混ざらないよう、`src/main.tsx` で別の画面へ移るときは読み込み直す。
- shadcn/ui に足した部品: Alert・Toggle・ToggleGroup（`npx shadcn@latest add`）。足した見た目: Badge の `ok`・`warn`・`fail`・`missing`・`wait`・`tag` と大きさ `field`、Button の大きさ `field`、Toggle の `field`。既存の画面で使っている見た目は変えていない。
- 判定のテストは `src/gauge/judge.test.ts`。
