# 計器盤（方向性A）— PC用Web画面のデザイン

本書はモック段階の設計仕様です。表示は架空データであり、実API・受信口・DBへの接続状態を示していません。

## 何のための画面か

最初の画面の役目は、QR付きの複数メーターを巡回した点検について、受信・読み取り・DB記録まで全部そろったかを確かめ、抜けや要確認に対処することです。使うのは、工場で点検する人と、記録を確認する人です。

- 点検ごとに、ルートの各メーターが「撮影→PCに到着→読み取り→記録」のどこまで進んだかを並べる。
- 各メーターの結果を小さな文字盤の絵で見せる。数字を読まなくても、外れたメーターが目に入るようにする。
- 最優先は視認性（ユーザーの追加条件「現場で見やすいように」）。飾りは、情報を読む邪魔にならない量にとどめる。

見本: 開発サーバーで `/#gauge`（点検の一覧）と `/#gauge/I-MULTI-20261112`（1件の点検の詳細）。既存の「機器」画面は `/` のまま。

## A-1の判定と集計

- 許容範囲外は読み取り成功・記録済みのまま対処対象とし、点検完了にはしない。一覧に「許容範囲外 N」の札、詳細に「許容範囲外」と「読み取り成功・記録済み」を出す。行・カードの帯と文字盤の印は黄土色の三角で区別する。
- 許容範囲は任意。未設定なら緑の帯は描かず、成功時は中立の「読取済」札と「許容範囲 未設定」、文字盤には中立の二重丸を出す。未設定自体は対処・完了判定を妨げない。
- 記録は stage >= 4、値あり、失敗以外。記録 ≤ 読み取れた ≤ 到着 ≤ 撮影を守る。
- 一覧のルート点検は撮影をルート台数、記録をルート撮影済み台数で割り、ルート外の記録は別行にする。詳細の到着・読み取り・記録はルート外を含むと明記する。
- 確認2: 既定はルート順。「要確認を上に」で切り替える。盤面は #E3E6E4。

## 状態の表し方（色＋文字＋形）

| 状態 | 文字 | 形（文字盤の下の印・札のアイコン） | カード・行の左端 |
|---|---|---|---|
| 正常 | 正常 | ● 塗りの丸 / CircleCheck | 細い緑の線（4px） |
| 要確認 | 要確認 | ▲ 三角 / TriangleAlert | 太い斜めの縞（10px、黄土と薄い地） |
| 失敗 | 失敗 | ■ 四角 / SquareX | 太い塗り（10px、赤錆） |
| 未撮影（撮り忘れ） | 未撮影 | ◌ 破線の丸 / CircleDashed | カード全体を紺の破線で囲む（内側のoutlineで左端の幅をそろえる） |
| 途中（PCに未着・読み取り待ち・記録待ち） | その段階の名前 | ◎ 二重丸（鋼） / Clock | 細い灰色の線 |
| ルート外（追加） | ルート外 | ⊕ / CirclePlus の札（状態とは別に付ける） | 状態に従う |

- 判定の規則（`src/gauge/judge.ts`）— **読み取りの成否を優先し、許容範囲は任意の補助情報にする**:
  1. `stage === 0` → **未撮影**（「撮り忘れ」）
  2. `status === "failed"`（`stage < 4` でも即判定）、または `stage >= 3 && value === null` → **失敗**（「値を読み取れなかった」）
  3. `stage < 4 || value === null` → **途中**（`PCに未着`／`読み取り待ち`／`記録待ち`。`stage === 3` で値があれば44pxの数値と針も出す）
  4. `stage === 4`（読み取り成功後）: `!id`（「名前なし」）・`status === "low_confidence"`（「読み取りが不確か」）・有効な目盛り範囲の外（「目盛り範囲の外」）→ **要確認**。それ以外 → **正常**。
  5. **許容範囲の外（`outOfTolerance`）**: 読み取り自体は成功しているので **kind は ok のまま**、表示は「許容範囲外」の札・黄土色の三角・注意領域の別枠で伝え、対処対象とする。許容範囲が未設定（`null`）や不正（下限＞上限）なら許容判定と帯を省き、「許容範囲 未設定」を示す。成功時は緑の正常札を中立の読取済札に置き換える。
- 一覧の行左端・注意枠・詳細の「要確認を上に」並びの優先順はすべて `未撮影 → 失敗 → 要確認 → 途中 → 正常`（正常内では許容範囲外を先頭）で統一する。
- 通信の受信完了と点検の完了を分けて示す（`src/gauge/status.tsx` `ReceiveBadge`）: `missing` / `fail` / `warn` がある点検には緑の「点検 完了」を出さず、「写真受信済み（要対処）」などの控えめな札にする。

## 余白・角丸・線

- 余白は4pxの倍数: 4・8・12・16・20・24・32。カードの内側は左右20px・上下16px、カード同士の間は12〜16px。
- 角丸は小さくする（機械の銘板に合わせる）: 3px（小）・4px（入力・札）・6px（カード）。
- 線: カード枠と区切りは不透明の細罫1px（`#B4BBBE`）、入力枠は罫1px（`#757F85`）、見出しの下は紺インク2px＋目盛りの定規（12pxごとの小目盛り、60pxごとの大目盛り）。
- 横幅は最大1760px。1366pxでは詳細のカードが3列、1920pxでは4列になる（`minmax(400px, 1fr)`）。

## 文字盤の絵（目玉）

`src/gauge/Dial.tsx`。SVGで、viewBox は 120×112。詳細のカードでは148px、一覧では52px（ミニ）。

- 目盛り: 240°（左下から右下まで、上を通る）。詳細は31本（5本ごとに長い大目盛り）、ミニは6本の大目盛りだけ（未撮影ミニでは目盛りを省く）。色は紺インク（目盛り未設定時は罫の色に落とす）。
- 許容範囲の帯: 半径43、太さ8（ミニは12）で、許容の下限から上限まで（目盛りの `[0, 1]` に収める）。色は帯 `#3E8A5C`。許容範囲が未設定・不正、または目盛り未設定のときは描かない。
- 針: 読み取り値の位置（`stage === 3` の記録待ちでも値があれば描く）。紺インク、太さ3（ミニは5.5）で、文字盤色の縁を付ける。目盛りの外の値は端を4%越えた所で止める（本物の計器の振り切れと同じ見え方）。中心の軸は紺の丸。
- 目盛りの両端の数字（最小・最大）: 詳細だけ、針があるときだけ。目盛り弧の内側（半径38、両端から角度を少し外した位置）に置き、中心部や目盛り線と重ならないようにする。
- **目盛り範囲なし・逆転・同値（`scale === null` または `min >= max`）**: 仮の `0〜100` を補わず、ゼロ除算も起こさない。針・帯・数値目盛りを描かず、詳細では中央に「目盛り未設定」を書き、右の44px読み取り値はそのまま見せる。
- **単位なし（`unit === null` または空文字）**: 余分な空白や仮の単位を付けず、右の読み取り値横に「単位未設定」を添える（許容範囲行の単位も省略）。
- 状態の印: 下の切れ目の中央に ● ▲ ■ ◌ ◎ を置く。ミニでも形で見分けられる大きさ（約13px）にした。
- 失敗（値なし）: 針を描かず、軸は白抜き。面に赤錆の斜線を敷き、中心の下に「読めず」と書く。
- 未撮影: ミニでは細かな目盛りを省く。外周を紺の破線（ミニは太さ3.5で視認性を確保）にし、目盛りを罫の色に落とし、帯と軸を描かない。中央に「未撮影」と書く。
- 途中: 値がまだ無いときは針を描かず軸を白抜きにし、中心の下に「待ち」と書く。`stage === 3` で値が読めているときは針を描く。
- 読み上げ: `role="img"` と `aria-label`（例:「No.3 SYN-002 冷却水 出口圧力。許容範囲外。読み取り値 36.75 kPa。許容 20.0〜35.0 kPa。許容範囲外」）。許容範囲が未設定なら許容部分は省く。

## 画面の構成

台数の単位はすべて **「台」** にそろえ、写真枚数だけが **「枚」** を使う（「件」と混ぜない）。

### 点検の一覧（`#gauge`）

1行が1件の点検。新しい順。上の切り替えで「すべて」と「対処が必要」を選ぶ。

```
[日付/時刻] [点検名 / ルート・担当 / 注意の札]   [ミニ文字盤×ルートの台数 | ルート外]   [撮影 4/5台 / 記録 4/4台 / ルート外 1/1台]   [受信・完了状態]  >
```

- 注意の札: 未撮影N・失敗N・要確認N・ルート外N（あるものだけ）。
- 受信・完了状態: 「点検 完了」（正常の札。受信完了かつ全台正常のときのみ）、「写真受信済み（要対処）」（控えめな札）、「写真受信済み（処理中）」（途中の札）、「不足あり N枚未着」（要確認の札）、「受信中 到着/撮影」（途中の札）。
- 行全体が詳細へのリンク。

### 1件の点検の詳細（`#gauge/<点検ID>`）

上から順に並べる。

1. 戻るリンク、点検名＋受信・完了状態、点検ID・ルート・担当・日時・写真の枚数。
2. 全体の進み具合（台数）: 撮影→PCに到着→読み取れた→記録 の台数。ルートがあるときは撮影の分母をルートの台数（例: `4/5台`）にし、ルート外は「＋ルート外 N台」として分けて示す。
3. 対処が必要なこと（許容範囲外を含む）: 未撮影・PCに未着・失敗・要確認・ルート外・許容範囲外をそれぞれ枠にまとめる。各機器はボタンになっており、押すと該当カードへスクロール＋フォーカスして即確認できる（未撮影機器を存在しない写真へリンクしない）。
4. ルートの機器のカード（**既定はルート順**。切り替えで「要確認を上に」）。カード上部は **機器名（18px太字）を上、No.・機器IDをその下** に置き、状態の札・文字盤・読み取り値・（任意）許容範囲・理由／補助注意・4段の進み具合（済み段は主値の紺と競合しない罫の色 `--g-rule`）・出所・撮影時刻を載せる。
5. ルート外の機器のカード（別の見出しで分ける）。

出所の言葉: スマホのQR／一覧から／手入力／PCの画像QR（2つ以上は「・」でつなぐ）。

## 歯車・計器の意匠

使う所（3か所だけ）:
- 左上の印（紺の四角に歯車のアイコン1つ）。
- 見出しの下の目盛りの定規。
- 文字盤の絵（情報そのもの）。

禁止:
- 歯車を回す、背景に歯車や計器の模様を敷く、カードの角に飾りの歯車を置く。
- 文字盤の絵を飾りとして使う（必ず実際の値や状態を表す）。
- 金属の質感、影の重ね、光彩、グラデーション、紫系の色、絵文字のアイコン、大文字の英語ラベルの字間を広げた見出し、中央揃えの多用。

## 動き

- 針: 値が変わったときだけ、400msで新しい位置へ回す（`cubic-bezier(.2,.7,.2,1)`）。表示したときの振り上げはしない。
- 進み具合の段: 段が進んだときに、200msで色を変える。
- 点滅・脈打つ動き・読み込みの飾りは使わない。
- `prefers-reduced-motion: reduce` のときは、すべての transition と animation を止める（注意枠からのジャンプも瞬時に移動）。

## 現場で見やすくする工夫

| 工夫 | 理由 |
|---|---|
| 状態を色・文字・形の3つで示す | 色覚の多様性への配慮と、灰色の印刷や低品質なモニターでも区別できるようにするため |
| 問題は塗り、正常は控えめにする | 一覧で問題のある行だけが目に入るようにするため |
| 左端の帯の太さと模様を状態で変える（細線・縞・塗り・破線） | 離れた所から、行の左端だけで状態が分かるようにするため |
| 文字盤の絵で許容範囲と針を見せる | 数字を読まなくても、外れた計器が目に入るようにするため |
| 読み取り値を44pxの太字にする | 離れた所からも読めるようにするため |
| 本文の最小を16pxにする | 作業着のまま、少し離れて画面を見る使い方を想定したため |
| 数字の桁幅をそろえる | 並んだ値を見比べるときに、桁の位置がずれないようにするため |
| 押せる所の高さを44pxにする（切り替え・戻る） | 手袋のままタッチパネルで操作する場合にも押しやすくするため |
| 撮り忘れのカードを破線で囲み、「未撮影」を3か所に書く | 「何もない」ことは見落としやすいので、形を変えて目立たせるため |
| 注意枠に、次にする操作と対象カードへの移動を置く | 何が起きたかだけでなく、どう直してどこを見るかまで即たどれるようにするため |
| 点滅や脈打つ動きを使わない | 長く見続ける画面で目が疲れないようにするため |
| 盤面を真っ白にしない（`#E3E6E4`） | 明るい工場の照明の下でのまぶしさを抑えるため |

## 実装メモ

- Tailwind（`@import "tailwindcss";`）と `@theme inline` は `src/index.css` に1回だけ置く。`src/gauge/gauge.css` の指定は `.gauge` の中だけに閉じ、`src/astryx/Comparison.tsx` は表示中だけ CSS を差し込むことで、`src/main.tsx` の `location.reload()` なしで `#`／`#gauge`／`#astryx` を切り替えても CSS が混ざらない。
- `index.css` の要素への指定（`p`・`h1`・`header` など）は層の外にあって強いので、`.gauge` の中では `all: revert-layer` で打ち消している。
- shadcn/ui に足した部品: Alert・Toggle・ToggleGroup（`npx shadcn@latest add`）。足した見た目: Badge の `ok`・`warn`・`fail`・`missing`・`wait`・`tag` と大きさ `field`、Button の大きさ `field`、Toggle の `field`。既存の画面で使っている見た目は変えていない。
- 判定のテストは `src/gauge/judge.test.ts`。

## DB・仕様の前提と残確認

- **既存のDB列**: `devices` テーブルには既に `unit`（単位）・`min_value`（目盛り下限）・`max_value`（目盛り上限）がある（`manager/devices.py`・`manager/storage.py`・`manager/inspection.py`）。今のDBに無いのは **運用上の許容範囲（`tolerance_min` / `tolerance_max`）だけ** であり、今後必要な機器だけ設定できる任意列として `devices` に足す方針（QRコードには入れない）。
- **今回の決定反映（2026-11-13）**:
  - 単位・目盛り範囲・許容範囲はいずれも任意扱いとし、未設定でも画面が壊れない。
  - 成功・失敗の判定は「値を読み取れたか」を優先し、許容範囲外は読み取り成功のまま対処対象にする（失敗・OCR不確かとは分ける）。
  - 詳細の並び順はルート順を既定とし、切り替えで「要確認を上に」を使える。
  - 盤面色 `#E3E6E4` は維持し、カードの枠を不透明細罫 `#B4BBBE` に変更。M3 `surfaceVariant` は `#D7DCDA` とした。
- **ユーザー最終確認待ち**: 再構築後の見た目（実画面・単体テスト）と上記の値に問題がなければ、本書の `合意:` を確定する。
