# 企業提供画像の取り扱いガイドライン

日本製鋼所様から受領した実機写真、および工場で撮影した写真の扱い方をまとめる。
**チーム全員が対象。** 分からない点があれば、自己判断せず本人（大久保）に確認すること。

---

## 大原則

**企業から受け取った画像を、外部へ一切出さない。**

「外部」とは、自分のPCとチームのSlack以外のすべてを指す。特に次は明確に禁止する。

| 禁止すること | 理由 |
|---|---|
| **GitHubへのコミット・push** | 一度pushすると履歴から完全に消すのは難しい。パブリック化・フォーク等で拡散する恐れもある |
| 生成AIサービスへのアップロード | ChatGPT / Gemini / Claude のWeb版・アプリに画像を貼らない。学習や保存の対象になりうる |
| クラウドストレージへの保存 | Google Drive / OneDrive / Dropbox 等の個人アカウント |
| SNS・ブログ・発表資料への掲載 | 卒論・発表で使う場合は事前に許可を取ること（後述） |
| チーム外への共有 | 他の研究室・友人・アルバイト先など |

**判断に迷ったら「出さない」を選ぶ。** 出してしまってから取り消すことはできない。

---

## 対象となる画像

以下はすべて「企業提供画像」として扱う。

- `C:\卒研\images\recieved_meter\` 配下（企業から直接受領した圧力計の写真）
- `C:\卒研\images\20260817_*.jpg`（工場で撮影した実機の写真）
- **上記を元に生成した画像**（検出結果を重ねたもの、切り出したもの、縮小したもの等）
  - 加工しても元の盤面・銘板・機器番号が写っていれば同じ扱い

**「加工したから大丈夫」ではない。** 機器番号（A-101 等）や銘板が読み取れる時点で、
どの設備の写真か特定できてしまう。

---

## リポジトリでの扱い

**画像はリポジトリに置かない。** ローカルの `C:\卒研\images\` に置き、
コードからは絶対パスで参照する。

`.gitignore` で次を除外している。

```
eval/overlays/
eval/overlays_*/
*_result.jpg
debug_*.jpg
```

### コミット前に必ず確認する

```powershell
git status
```

**見覚えのない `.jpg` / `.png` が「Untracked files」や「Changes to be committed」に
出ていないか確認すること。** 特に `git add -A` や `git add .` を使うときは要注意。
まとめて追加すると、意図しない画像が混ざる。

安全な習慣として、**変更したファイルを個別に指定して add する**ことを勧める。

```powershell
git add tick_detect.py tests/test_tick_detect.py
```

### 誤ってコミットしてしまったら

**push する前なら取り消せる。慌てず、すぐ本人（大久保）に連絡すること。**
自分で `git reset --hard` 等を試すと、他の作業まで消える恐れがある。

**push してしまった場合も、必ずすぐ報告すること。** 対応が早いほど影響を小さくできる。
黙っているのが最悪の選択。

## テスト・検証で画像が必要なとき

**git管理下にある非工場データを使う。**

| 用途 | 使うもの |
|---|---|
| 目盛り検出・中心推定のテスト | `eval/images/meter1.png` 〜 `meter4.jpg`（ストック画像） |
| 回帰テスト | `tests/fixtures/`（検出ログ、画像そのものではない） |

企業提供画像は**手元での動作確認にのみ**使い、結果は数値やスクリーンショットの
説明として共有する（画像そのものは共有しない）。

---

## AIに相談するとき

**画像をアップロードしない。** 代わりに次のように伝える。

- 「丸型の圧力計で、白い盤面に黒い目盛り、0〜150MPaのレンジ」のような**言葉での説明**
- エラーメッセージやコードの中身（これらは問題ない）
- 検出結果の**数値**（座標、検出本数、誤差など）

画像を見せないと解決できない場合は、**ストック画像（meter1〜4）で再現するか、
本人（大久保）に相談すること。**

---

## 卒論・発表で使う場合

**事前に許可が必要。** 先生経由で日本製鋼所様に確認を取る。

現在、写真の外部利用可否は**確認中**（`tasks/先方への確認事項.md` の質問9）。
回答が来るまでは、論文・発表資料への掲載も控えること。

代替案として、ストック画像（meter1〜4）や、機器番号・銘板をぼかした画像を
使う方法もある。どうするかは回答が来てから判断する。

---

## なぜここまで厳しくするか

これは共同研究であり、**相手の設備の情報を預かっている**という立場にある。
写真には機器番号・定格・設置状況が写っており、外部に出れば相手方の
セキュリティ上の問題になりうる。

研究の成果がどれだけ良くても、ここで信頼を損なえば取り返しがつかない。
**面倒でも、毎回確認する習慣をつけてほしい。**
