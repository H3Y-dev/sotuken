## 議題1: キューAPI（`ui/` と `queue/` の境界）

`ui/`（SKくん）が `queue/`（本人）を呼ぶ入口は、次の2関数だけとする。ここ以外から触らない。

### 叩き台（`android/app/src/main/kotlin/jp/sotuken/metercapture/queue/QueueStore.kt` に実装済み）

```kotlin
suspend fun enqueue(imageFile: File, meta: CaptureMeta): String   // 戻り値は localId
fun observeQueue(): Flow<List<QueueItem>>
```

```kotlin
data class CaptureMeta(
    val deviceName: String?,      // 機器名。未入力可
    val operatorValue: Double?,   // 現場で入力した真値。未入力可
    val operatorNote: String?,    // 備考。未入力可
)

data class QueueItem(
    val localId: String,          // UUID。端末が採番する
    val imagePath: String,
    val capturedAt: String,       // ISO 8601
    val deviceName: String?,
    val operatorValue: Double?,
    val operatorNote: String?,
    val sendState: SendState,     // PENDING / SENDING / SENT / FAILED
    val retryCount: Int,
    val lastError: String?,
    val sentAt: String?,
)
```

状態遷移: `PENDING → SENDING → SENT`、失敗時 `SENDING → FAILED`、再送時 `FAILED → PENDING`。
アプリ起動時に `SENDING` のまま残っている項目は `PENDING` へ戻す。

### 決めること

- [ ] 上記2関数のシグネチャをこのまま確定してよいか
- [ ] 状態名は `PENDING / SENDING / SENT / FAILED` の4つでよいか（増やさない）
- [ ] `capturedAt` の形式。**叩き台は `Instant.now().toString()`（UTC・末尾Z）。**
      現場の担当者が見る時刻とズレるが、PC側で機械的に扱いやすい。ローカル時刻＋オフセットにするなら今決める
- [ ] `operatorValue` は `Double?` でよいか（文字列で受けて後で数値化する案と比較）
- [ ] リスト画面の表示4項目（サムネイル・撮影日時・送信状態・機器名）は `QueueItem` だけで足りるか

### 決定（2026-09-07、本人単独で確定。全員同席の場は設けていない）

上記のまま確定した（`QueueStore.kt`/`QueueItem.kt`に実装済みの形と一致）。

- シグネチャ・状態名4つ・`capturedAt`（UTC・`Instant.now().toString()`）はそのまま確定
- `operatorValue`は`Double?`のまま確定（文字列入力からの数値化はUI側の入力フォームの責務とし、キュー層は数値だけを持つ）
- リスト画面の表示4項目は`QueueItem`だけで足りる（サムネイルは`imagePath`から生成できる）

## 議題2: サイドカーJSON（端末 → PC の受け渡し）

公開フォルダ経路では、画像と**同じベース名**のJSONを1つ添える。

### 叩き台

ファイル名: `YYYYMMDDTHHMMSS_<local_id>.jpg` と `YYYYMMDDTHHMMSS_<local_id>.json`

```json
{
  "local_id": "3f9c1e2a-....",
  "captured_at": "2026-09-02T01:35:14Z",
  "device_name": "圧力計A",
  "operator_value": 0.5,
  "operator_note": "昇圧前"
}
```

**この5項目だけを載せる。**PC側が付ける項目（`reading_id`・`received_at`・`processed_at`・
`status`・`confidence`・`pipeline_version` など）は端末が知らないので入れない。
特に **`reading_id` はPC側が採番する。**端末は `local_id` しか持たない。

置く順序: **JSONを先に置き、画像を後に置く。**取り込み側は画像の出現を開始条件にする。
書き込みは一時名で行い、書き終えてから正式名へリネームする（コピー途中の部分ファイルを掴まないため）。

### 決めること

- [ ] 項目名を上記5つで確定してよいか（`snake_case`。Kotlin側の `camelCase` とはここで変換する）
- [ ] 未入力の項目は `null` を書くか、キーごと省略するか。**どちらか一方に統一する**
- [ ] 拡張子は `.jpg` 固定でよいか（HEIC等が出る端末なら今決める）
- [ ] ファイル名の `local_id` はUUIDそのまま（36文字）でよいか、先頭8文字に短縮するか
- [ ] 一時名の付け方（例: `.part` を付ける / 先頭に `_` を付ける）

### 決定（2026-09-07、本人単独で確定。全員同席の場は設けていない）

- **項目名は上記5つ（`local_id`/`captured_at`/`device_name`/`operator_value`/`operator_note`）で確定。** SRくんの設計メモの記述と一致する
- **未入力の項目は `null` を明記する（キーは省略しない）。** PC側のパーサが「キーが無い」と「値がnull」の両方をハンドルする必要をなくすため
- **拡張子は `.jpg` 固定。** 現行のAndroidカメラ撮影パスはJPEG出力のみを想定（Sprint 3のSK-03でカメラ実装時にJPEG固定で揃える）。HEIC等が出た場合は別途決める
- **`local_id` はUUIDそのまま（36文字）を使う。** 短縮すると衝突確率が上がり、現場での可読性より一意性を優先する
- **一時名は `<正式名>.part` を末尾に付与する方式。** 例: `20260907T053000_<uuid>.json.part` → 書き終えたら `20260907T053000_<uuid>.json` へリネーム。画像も同様（`.jpg.part` → `.jpg`）

**注意**: 議題1と同じく、本人の判断で先に決めた。SRくんの設計と矛盾しない内容だが、次回異論があれば訂正する。

## 議題3: PC側の監視フォルダ命名規則

PCは無線・有線を区別せず、**フォルダに画像が置かれた場合だけ**を受け口にする。

### 叩き台

```text
C:\卒研\meter_inbox\
├── incoming\    ← 端末・HTTP受信の両方がここへ置く（監視対象）
├── processing\  ← 取り込み中に移す
├── done\        ← 取り込み済み
└── error\       ← 対の相手が無い・読めない等
```

出力側（PC）は仕様書どおり `images/<image_sha256>.<拡張子>`、`logs/<reading_id>.log`、
`overlays/<reading_id>.png`、集約は `readings.csv` と `readings.jsonl`。

### 決めること

- [ ] 監視ルートのパスを確定する（全員が同じ文字列を使う。ハードコードせず設定値にする）
- [ ] 対になる相手が無いファイルの扱い（何分待って `error\` へ移すか）
- [ ] 同じ `image_sha256` を再取り込みしたときの動き（二重登録しない。原画像も上書きしない）

### 決定（2026-09-07、本人単独で確定。全員同席の場は設けていない）

- **監視ルートは `C:\卒研\meter_inbox\` を既定値とする。** SRくんの設計メモと一致。各自の環境でルートを変える必要が出た場合のために、コードへ直書きせず設定値（環境変数か設定ファイル）で持たせる。この設定の実装自体はSRくん（PC側取り込み）の担当範囲とする
- **対になる相手が無いファイルは5分待って `error\` へ移す。** バッチの定期実行間隔と揃えやすい値として仮置きし、実運用で長すぎ/短すぎが分かれば調整する
- **同じ `image_sha256` の再取り込みはスキップし、ログにのみ記録する。** 二重登録・原画像の上書きはしない（SRくんの設計メモの記述どおり）

**注意**: 議題1・2と同じく、本人の判断で先に決めた。SRくんが実装するPC側の範囲なので、次回SRくんに直接確認すること。
