## 1. 環境を同期する手順（最初に必ずこれをやる）

**普段通りの `git pull` や `git rebase` ではなく、以下のコマンドで `origin/SRdevelopment` を丸ごと取り込んでください。** 上記の統合はSRくんの手元にある未pushの変更を壊す可能性があるため、**作業を始める前に `git status` で未コミットの変更が無いことを確認してから**実行してください。

```
git status
git fetch origin
git checkout SRdevelopment
git reset --hard origin/SRdevelopment
```

**注意: `git reset --hard` は手元の未コミット・未push の変更を消します。** 何かローカルに残っている変更があれば、先に `git stash` するか、本人（大久保）に相談してから実行してください。

同期できたか確認:

```
venv\Scripts\python.exe -m unittest discover -s tests
venv\Scripts\python.exe -m unittest discover -s manager -p "test_*.py"
```

`tests` 側が26件ではなく**50件**、`manager` 側が**7件**出ればmainの取り込みが効いています。

## 2. 今後 `main` と同期するときの注意（再発防止）

**今回の原因は、`git stash` を挟んだ手動マージ中に `manager/test_manager.py` へ実装コードが混ざり込んだことでした。** 次から `main` を取り込むときは:

- **`git rebase origin/main` の前に、必ず `git status` で作業ツリーが綺麗（コミット済み）なことを確認する。** stashを挟んだ状態でrebase系のコマンドを使わない
- コンフリクトが出たら、**その場でファイルの中身を見て「実装コードとテストコードが混ざっていないか」を確認する。** `manager/test_manager.py` に `class MeterManager` や `def process_image` のような行が出てきたら、それは壊れているサインなので、無理に自分で解決せず本人（大久保）に相談する
