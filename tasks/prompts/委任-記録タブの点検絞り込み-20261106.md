## 背景
スマホアプリ(Android)に「点検」(工場内の複数メーターを読んで回る単位)を追加する予定。スマホは写真1枚ずつに点検IDを付けて送る。PC側で、記録タブを点検ごとに絞り込めるようにしたい。スマホ側はこれから作る(別の作業)ので、**PC側は、点検IDが付いていない既存のデータ・既存のスマホでも、今までどおり動くこと**が最優先。

## 契約(スマホとPCの取り決め。この通りに実装する)
サイドカーJSONの新しい任意キー:
- `inspection_id`: 文字列。`[A-Za-z0-9._-]` の1〜64文字。例 `20261106T093000-k3f9`。空・不正な形式なら無効として扱う(捨てるだけで、記録自体は受け付ける。機器IDの `id_invalid` と同じ流儀で、問題の印を残してよい)。
- `inspection_name`: 文字列、前後の空白除去後1〜64文字、制御文字なし。任意。無ければ NULL。
- 同じ inspection_id で名前が違う写真が来たら、最初に入った名前を維持する(後から上書きしない)。

## 実装してほしいこと
1. **DB**: `meter_readings` に `inspection_id TEXT`、`inspection_name TEXT`(どちらも NULL 可)を追加する。既存DBは、起動時の安全なマイグレーション(既存の流儀に合わせた ALTER TABLE ADD COLUMN。既存行は NULL)。新しい列のインデックスを inspection_id に付ける。
2. **取り込み**: sidecar.py のパース、receiver の `validate_sidecar_metadata`(新キーの検証。無効でも受信は拒否しない)、storage.py の保存、取り込み処理(watch_inbox など、サイドカーを読んでDBに入れる経路)で、新しい2列を保存する。後着サイドカー(画像が先、JSONが後)でも反映される。
3. **再処理**(manager/reprocess.py): B6と同様に、新しい2列を引き継ぐ(device_id等と同じ扱い)。
4. **記録タブ**(app.py と、その一覧を作る関数): 既存の機器名・開始日・終了日の絞り込みに、「点検」の選択を足す。選択肢は「すべて」「点検なし(旧データ)」と、DBにある点検(表示は `inspection_name`(無ければ `inspection_id`)+ 件数)。選ぶと一覧と件数が絞られ、他の絞り込みと併用できる。一覧の列にも点検名を出す。
5. **書き出し**(manager/export.py の JSONL/CSV): 新しい2列を含める。既存の列の順序・名前は変えない(末尾に追加)。絞り込みの結果と書き出しの件数が一致すること(既存の保証を維持)。
6. 点検結果タブ(inspection_ui.py / inspection.py): 変更は不要。ただし、名前が紛らわしいので、画面の見出しの違い(「点検結果」=機器ごとの判定、新しい「点検」=現場の巡回単位)が分かる文言を、記録タブの選択肢のラベルに入れる(例: 「点検（巡回）」)。
