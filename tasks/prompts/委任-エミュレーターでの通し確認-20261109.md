## 背景（卒研の中身）
製造現場のメーター（圧力計・温度計など）を、スマホアプリで撮影し、PCへ送り、画像から針の値をOCR・画像処理で読み取ってDBに記録するシステム。
- スマホ: `android/`（Kotlin/Compose）。点検を作り、点検ルート（PCで作る機器一覧）に沿ってメーターを巡回撮影し、完了すると送信待ちになり、PCの受信口に届く接続が確認できたら写真を1枚ずつ自動送信、最後に点検IDつきmanifestを送る。
- PC: `run_pc.py`（受信口 :8765 とStreamlit画面 :8501）、`manager/`（受信・取り込み・DB・点検ルート・点検状態判定）、`watch_inbox`（incoming/を監視して取り込み）。
- 通し: 「点検ルート作成(PC) → スマホでルート取得(Wi-Fi/QR) → 点検作成 → 各メーターを撮影 → 履歴確認 → 点検完了 → 自動送信 → PCの記録タブに点検ごとに表示」。
- 実機（SM_F966Q, Android 16）での通しは未実施。今回は**エミュレーター（AVD `Pixel_5`、Android 11）で疑似的に通す**のが目的。実機のWi-Fi切替・USBテザリング・カメラ画質は対象外。

## ゴール
`tools/emulator_e2e/`（新規）に、次を1コマンドで再実行できるスクリプト一式と、実行結果の報告を作る。
1. **PC側を隔離して起動**: 一時ディレクトリに別のDB・incoming・設定（`manager/pc_config.json`相当は環境変数や引数で差し替えられるか調べ、本番の`manager.db`・`incoming/`・既存の起動中プロセス(:8765,:8501)に触れない。ポートが衝突するなら別ポート）。点検ルートを1本作る（機器2〜3台、`tools/`や`manager/`の既存関数を使う）。
2. **エミュレーター起動とAPK導入**: `%LOCALAPPDATA%\Android\Sdk\emulator\emulator.exe -avd Pixel_5`（`-no-snapshot`、`-no-audio`。ヘッドレスは`-no-window`でよい）。起動待ち（`adb wait-for-device`＋`sys.boot_completed`）。APKは`android/`で`gradlew assembleDebug`（既にあれば再利用可）。`adb install -r`。adbは`%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`。エミュレーターからPCは`http://10.0.2.2:<port>`。
3. **アプリ操作の自動化**: `adb shell input`と`uiautomator dump`で、送信先設定 → ルート取得（QR取り込みはカメラが要るので、取り込めない場合は設定画面への手入力 or ルート取得APIの手動指定など、実機と同じ経路にできる範囲で代替し、代替した点を報告に明記）→ 点検作成 → 撮影 → 完了 → 自動送信、まで。
4. **撮影の代替**: カメラの代わりに、エミュレーターの仮想カメラ（`hw.camera.back=virtualscene`や、画像を映す設定）を使うか、難しければ`adb push`した画像をアプリが受け付ける経路（ギャラリー取り込み等が無ければ、アプリの送信箱に直接ファイル＋サイドカー(JSON)を置く方法）を使う。どの方法で何を代替したかを報告に書く。テスト画像は`C:\卒研\合成画像\テスト用QR付き_20261030\`配下の数枚（機器QR付き）。
5. **PC側の検証**: 受信 → 取り込み → DB → 記録タブ相当のデータ（点検状態が「完了」、機器ごとの読み取り行）を、SQLiteとAPI(`GET /routes`等)から検証し、合否をスクリプトが出力する（期待値と照合）。
6. **異常系を最低1つ**: 送信中にPC受信口を止めて「未送信」→再開で追い送り、二重登録なし（重複なし）を確認。エミュレーターのネットワーク切断（`adb shell svc wifi disable`や受信口の停止）で再現。
7. 後始末: エミュレーターとPC側の一時プロセスを必ず止める。
