## 3. 手順

### 3-1. まず最新を取り込む

**2026-09-03に大久保の方でmainが3回更新されています**（Androidのテスト基盤、実機用の計装テスト、KPくんの成果）。着手前に取り込んでください。

```
git fetch origin
git rebase origin/main
```

取り込めたかは、`android/app/src/test/` と `android/app/src/androidTest/` の2つのフォルダが存在するかで判別できます。

### 3-2. ビルドする

Android Studioで `Build > Make Project` を選びます。コマンドなら、リポジトリの `android` フォルダで次を実行します。

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat assembleDebug
```

**成功すると `app/build/outputs/apk/debug/app-debug.apk` ができます**（12MB程度）。

**エラーが出たら、自分で設定を書き換える前に `android/README.md` の「ビルドで詰まったときは」を読んでください。** 2026-09-03に出たエラーは全部そこに載せてあります。**`gradle/libs.versions.toml` のライブラリのバージョンは絶対に上げないでください。** AGP 8.13.2 で通る組み合わせに揃えてあるので、上げると逆に通らなくなります。

そこに載っていないエラーが出たら、**エラーメッセージをそのままコピーして大久保へ送ってください。**

### 3-3. 実機を繋ぐ

ここが一番詰まりやすいところです。

1. `設定 > 端末情報` で `ビルド番号` を**7回タップ**して開発者向けオプションを有効にします（PINを聞かれたら入力）
2. `設定 > システム > 開発者向けオプション` で **`USBデバッグ` をオン**にします
3. USBで接続し、**端末のロックを解除**します
4. 端末の通知から `USBの用途` を **`ファイル転送`** に変えます。`充電のみ` のままだとPCから見えない機種があります
5. 「USBデバッグを許可しますか」が出たら、**「常に許可する」にチェックして許可**します

繋がったかどうかを、必ずコマンドで確認してください。

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
```

`<端末ID>  device` と出れば成功です。何も出ない、`unauthorized`、`offline` の場合の対処は `android/README.md` の「端末が認識されているか確かめる」にあります。**充電専用のUSBケーブルだと認識しません。** データ転送対応のものを使ってください。

### 3-4. 起動する

Android Studio上部のデバイス選択欄で端末を選び、緑の実行ボタン（Run）を押します。

## 4. 受け入れ条件

- [ ] 起動した画面のスクリーンショットを大久保へ共有できる

**「キュー: 0件」のままで正常です。** キューへ入れる手段がまだ実装されていないので、件数は増えません。ボタンも一覧もカメラも出ません。**それで受け入れ条件は達成です。** 画面が寂しいからといって何かを追加しないでください。

参考までに、**大久保の端末（Galaxy Z Fold）では2026-09-03に起動確認済みです。** 同じ画面が出れば成功です。

作れたら、エミュレータでも同じ画面が出ることを確認してください。**なお、エミュレータにカメラはありません**（仮想の映像が出るだけです）。Sprint 3のカメラ作業と工場での確認は実機が必須です。

## 6. 守ってほしいこと

- 着手前に必ず `git fetch origin` と `git rebase origin/main` を実行する
- 企業提供画像・DBファイル（`manager.db`）・出力CSVをコミットしない。`git add -A` は使わず、変更したファイルを個別に指定して add する
- `print()` に絵文字を使わない（Windowsのcp932でUnicodeEncodeErrorになる）
- **ビルドが通らないときにライブラリのバージョンを上げない。** 大久保へ相談する
- 新規アプリ作成、雛形の作り直し、`queue/` の変更、カメラ権限の実行時リクエスト実装はしない
- 分からないことがあれば大久保に聞く


`git status` に見覚えのないファイル、特に企業提供画像・`manager.db`・出力CSVが出ていないか確認してください。**今回はコード変更が不要なはずなので、コミットやpushはせず、起動結果を大久保へ共有してください。**

## 8. 最後に必ずやること：日報を書く

今回の作業が終わったら（途中で終わった場合も含めて）、日報をMarkdownファイル1枚にまとめてください。
ファイル名は `日報_<名前>_<YYYYMMDD>.md` です。書く内容は次の8項目です。
**分からない項目は「なし」と書き、空欄にしないでください。**

1. **名前と日付**
2. **今日のタスク名**（タスクIDを付ける。例: SK-02 Android雛形を実機で起動する）
3. **やったこと** — 実際に手を動かした内容を3〜5行で。やろうとしたが着手できなかったことは、そう書く
4. **成果物** — 作成・変更したファイルのパス。コミットしたなら**コミットのハッシュ（先頭7文字）と
   ブランチ名**も書く。コミットしていないなら「未コミット」と書く
5. **テスト結果** — 実行したコマンドと、何件中何件パスしたか。実行していないなら「未実行」と、その理由
6. **受け入れ条件の達成状況** — 渡された受け入れ条件を1つずつ書き出し、達成／未達成を付ける
7. **詰まったところ・分からなかったこと** — **ここが一番大事です。** 解決できなかった点、判断に迷った点、
   推測で進めた箇所を正直に書いてください。「特になし」で済ませず、少しでも自信のない箇所は書き出してください
8. **次に必要なこと** — 次回やること、または大久保に判断・確認してほしいこと

### 日報を書くときの注意

- **できなかったことを隠さないでください。** 進捗が無かった日も、どこで止まったかが分かれば次の手を打てます。
  うまくいったように書かれるのが一番困ります
- **推測で断定しないでください。** 確認していないことは「未確認」と書いてください
- 企業提供画像そのものや、その内容が分かる記述を日報に含めないでください
- 絵文字は使わないでください（Windowsのcp932で文字化けします）
