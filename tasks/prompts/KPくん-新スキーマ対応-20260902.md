## 2. まず使う項目の対応を確認する

| 新スキーマの項目 | 3関数での使い方 | 意味 |
|---|---|---|
| `device_name` | `filter_readings` と `group_by_device` | 機器名 |
| `captured_at` | `readings_to_series` の時刻 | 撮影日時 |
| `value` | `readings_to_series` の値 | 読み取り値。失敗時は `None` |
| `status` | 読み取りの自動結果を表す | `ok` / `low_confidence` / `failed` |
| `input_method` | 最終値の出所を表す | `auto` / `manual` / `corrected` |

`status` と `input_method` は別のものです。たとえば自動読み取りに失敗して、人が手で値を入れたときは `status=failed` と `input_method=manual` が同時に入ります。この2つを1つの判定に混ぜないでください。

## 3. 使わない項目について

レコードには上の5つ以外にも項目があります（`reading_id`、`unit`、`confidence`、`image_sha256`、`pipeline_version` など、全部で17項目）。**今日の3関数はそれらを触りません。** 関数が知らない項目が入っていても、そのまま無視して動けばよいです。全部を覚える必要はありません。

失敗した記録も必ず残ります。読み取りに失敗したレコードは `value` が `None`、`status` が `failed` で入ってきます。`readings_to_series` はグラフに描けないので、これまでどおり `value` が `None` のものを除いてください。

## 4. なぜ必要か

一覧やグラフの担当者が、同じ機器の値だけを時刻順に見られなければ、工場で「この圧力計は昨日から上がっているか」を確認できません。新しい記録形式になっても、既存の3関数が使えれば、次のCSV・JSON Lines出力や画面表示につなげられます。
