## 問題
送信先(PC)を設定し直すと、送信箱に残っている古い写真も新しいPCへ送られる。QueueItemに宛先の識別子がなく、QueueSendWorkerが「現在の設定」でSenderを作るため。

## 実装してほしいこと
1. QueueItem(android/.../queue/QueueItem.kt)に `receiverId: String?` を足す。撮影(キューに積む)時に、そのときの ReceiverSettings.receiverId(QR登録で保存済み、PR #109)を入れる。手入力設定などでreceiverIdが無い/空のときは null(=宛先未固定)。
2. 既存のキューJSON/保存データを壊さない(フィールドが無い古いデータは null で読める。デフォルト値と読み込みの互換をテストで示す)。
3. 送信判定(SendRouter/QueueSendWorker): 項目の receiverId が null なら従来どおり現在の設定へ送る。非nullで、現在の設定の receiverId と一致すれば送る。**非nullで不一致なら送らず保留(HELD相当。状態の持ち方は既存のstatus/フィールドに合わせ、最小の追加にする)。** 保留は失敗扱いにしない・自動で消さない・再試行ループにしない。
4. 履歴画面(QueueDisplay.kt / QueueListScreen.kt)に保留の表示「別のPC宛て(保留)」と、保留項目だけの操作「今のPCへ送り直す」(押すと receiverId を現在のものに更新して送信対象に戻す。確認ダイアログを1つ挟む)を足す。UI変更は最小にする(SK-09のPRが同じ2ファイルを触るので、既存の関数・ブロックの並びを動かさない。足す分は新しい関数に分ける)。
5. 重複防止: 保留→現在PCへ送り直しても、PC側のSHA-256重複検出(409)があるので二重登録されない前提を崩さない。
