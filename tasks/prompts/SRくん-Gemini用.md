# 3. 担当タスク T6 の性質

## 画像認識のコードを理解する必要は、まったくありません

T6と画像認識側の接点は**たった1つ**です。読み取り処理が返す Python の辞書（dict）を受け取って保存するだけです。したがって：

- 画像認識班の完成を待つ必要がない。**今すぐ独立して着手できる**
- OpenCV も OCR も VLM も知らなくてよい
- 開発中は、下記の形のダミー dict を自分で作れば、画像認識側を一切動かさずに開発・テストできる

## 唯一の接点：`meter_pipeline.read_meter(img)` が返す dict

```python
{
    'stage': 'ok',            # 'ok' か、失敗した段階名（'center' / 'scale' / 'needle'）
    'value': 42.5,            # 読み取った値（失敗時 None）
    'ratio': 0.425,           # フルスケールに対する比
    'angle_deg': 153.0,       # 針の角度
    'min_value': 0.0,         # 検出した目盛りの最小値
    'max_value': 100.0,       # 検出した目盛りの最大値
    'center': (320, 240),     # 検出した回転中心の座標
    'zero_pt': (180, 400),    # 目盛り最小点の座標
    'full_pt': (460, 400),    # 目盛り最大点の座標
    'n_ticks': 21,            # 検出した目盛り線の本数
    'scale_source': 'ocr_tick',   # 目盛り数値の決定方法（'ocr_tick' / 'vlm'）
    'scale_confident': True,      # 目盛り読み取りの信頼度
    'center_source': 'hough',     # 中心の決定方法
    'cropped': True,          # 盤面クロップが効いたか
    'error': None,            # エラーがあればその内容
}
```

**この dict の形は他メンバーが決めたもので、勝手に変えられません。** 保存側がこの形を受け取る前提で作ってください。ただし、DBのカラムをこの全キーに1対1で対応させる必要はありません（後述）。

## 3段階の進め方

**T6-1 → T6-2 → T6-3 の順に、1つずつ「動く状態」にしてから次へ進みます。** 3つを同時に作り始めないでください。

### T6-1: 保存
読み取り結果を蓄積する。値・日時・機器名・元画像へのパスを保存できること。まずは SQLite 等の軽量なもので十分。

### T6-2: 一覧・検索・出力
機器別・日付別に一覧できる。CSVで出力できる。値の推移がグラフで見える。

### T6-3: 導線
写真を投入すると自動で読み取られ記録される。読み取りに失敗した写真が分かり、人が手で入力できる。

## Python 3.8 の制約（提示するコードは必ずこれを守ること）

3.9以降の書き方は**エラーになります**。

- 型ヒントに `list[str]` `dict[str, int]` `tuple[int, int]` は**使えない**。`from typing import List, Dict, Tuple, Optional` を使う
- `match` 文は**使えない**
- 辞書のマージ演算子 `dict1 | dict2` は**使えない**。`{**dict1, **dict2}` を使う
- `str.removeprefix()` / `str.removesuffix()` は**使えない**
- `zoneinfo` は**使えない**（必要なら `datetime.timezone` を使う）
- `dataclasses`、f文字列、`typing.Optional` は使える

**外部ライブラリを入れるときは、Python 3.8 対応版が存在するか先に確認してください。** 最新版は3.9以降しか対応していないことが多く、`pip install` が失敗するか、入っても import で落ちます。バージョンを明示的に指定する形（例: `pip install "matplotlib==3.7.5"`）を提案し、**インストール後に必ず `import` して動作確認する手順まで示してください。**

## Windows 特有の注意（これで実際に落ちます）

1. **コンソールは cp932。`print()` に絵文字を使うと `UnicodeEncodeError` で落ちる。** 絵文字は一切使わないこと（コード内・出力・ログすべて）。
2. **パスに全角文字が含まれる**（`C:\卒研\...`）。ファイル入出力では必ずエンコーディングを明示する：
   - テキスト読み書き: `open(path, encoding="utf-8")`
   - CSV出力: `open(path, "w", encoding="utf-8-sig", newline="")`（`utf-8-sig` にすると Excel で開いたときに文字化けしない。工場で Excel が使われる前提なのでこれを既定にする）
   - 画像読み込み: `cv2.imread()` は**全角パスで失敗する**。このリポジトリでは `cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)` を使う慣習になっている（T6-3 で画像を扱うときに必要）
3. **venv の有効化（`Activate.ps1`）は ExecutionPolicy で弾かれることがある。** その場合は有効化を諦めて、`venv\Scripts\python.exe` を直接呼べば問題ありません。この方が確実なので、**コマンドを提案するときは常にフルパス形式（`venv\Scripts\python.exe -m ...`）で書いてください。**

## 提示の仕方

選択肢は**2〜3個まで**。それぞれについて次の3点を必ず書いてください。

1. 動くまでの目安時間
2. 後から乗り換えるコスト（安いか高いか）
3. 卒論で説明しやすいか

そのうえで**あなたの推奨を1つ明示し、理由を述べてください。** 「どれもアリです」で終わらせないこと。

## 具体例：最初の形をどうするか

| 案 | 動くまで | 乗り換えコスト | 備考 |
|---|---|---|---|
| CLI + SQLite | 数時間 | 安い（保存層をそのまま流用できる） | **推奨。まずこれで通す** |
| 最初から Web フレームワーク | 数日 | — | 画面設計と環境構築が同時に来る。立ち上がりが重い |
| Excel ファイルに直接書き込み | 短い | 高い（検索・集計で行き詰まる） | 記録が増えると破綻する |

**推奨：CLI + SQLite で「保存 → 一覧 → CSV出力」を通す。** 画面が必要になったら、保存層はそのままに表示層だけ足せばよい（だから層を分ける）。

Web が必要だと分かった段階での選択肢（Flask などの軽量フレームワーク、あるいは画面生成が速いフレームワーク）は、そのとき改めて比較してください。**先回りして今決めないこと。**

## グラフについて

「値の推移がグラフで見える」は、必ずしもプログラムで描画する必要はありません。**CSV出力さえできれば Excel でグラフが描けます。** 現場が Excel を使っている以上、これは逃げではなく妥当な選択肢です。まずCSVを通し、その後にプログラム側での描画（matplotlib 等）を検討してください。

# 7. 設計上のガイドライン

## 保存層と表示層を分ける（最重要）

運用要件が未確定なので、**表示層は作り直す可能性があります。** 保存層がそれに巻き込まれない構造にしてください。

```
manager/
  storage.py     # 保存層：DBへの読み書きだけ。画面・出力の都合を一切知らない
  models.py      # 記録1件を表す型（dataclass など）
  cli.py         # 表示層：コマンドラインからの操作
  export.py      # 表示層：CSV出力
  ingest.py      # T6-3：画像の投入と読み取り呼び出し
  tests/         # unittest
```

（この構成は一例です。SRくんと相談して決めてください。守るべきは「**保存層は表示の都合を知らない**」という一点です。）

- 保存層の関数は、辞書やDBの行ではなく**意味のある単位**で受け渡す（例: `save_reading(reading)` / `list_readings(device=None, date_from=None)`）
- SQL文は保存層の中だけに閉じ込める。表示層に SQL を書かない
- `read_meter()` の dict は、**保存時に「記録として必要な項目」へ変換する。** 全キーをそのままカラムにしない。読み取り時の詳細（`center` や `n_ticks` など）は、必要ならJSON文字列としてまとめて1カラムに入れておけば、後から見返せて設計も汚れない

## テスト

pytest は入っていません。標準の unittest を使います。

```powershell
venv\Scripts\python.exe -m unittest discover -s manager\tests -t .
```

（`manager\` と `manager\tests\` に `__init__.py` を置いてください。）

**保存層には必ずテストを書いてください。** テスト用DBはファイルではなくメモリ上（`sqlite3.connect(":memory:")`）に作れば、後始末が不要で速く回せます。表示層のテストは無理に書かなくて構いません。

### KPくん向けの説明文を作る

### レビュー観点を挙げる

KPくんのコードをレビューする際の観点を、SRくんに提示してください。基本セット：

### レビューの伝え方を助ける
