## 1. SK-06のPR化の手順

作業中の内容は、先に渡した指示書にあります。
`tasks/prompts/SKくん-SK-06リスト画面と履歴-20261022.md`（GitHubのmainにあります）

手順（この順で、1つずつ）:

1. **今の状態を確認する。** `git status` と `git log -3 --oneline` の結果をAIに見せ、SK-06の変更が未コミットで残っていることを確かめる。
2. **最新のmainに合わせる。** 手元の変更を失わないように、AIと相談してから行う。
3. **テストを通す。** `gradlew test --rerun-tasks` を1回流し、成功した件数を控える。
4. **実機で確認する（できれば）。** 履歴画面で、撮影した画像の一覧が出る・タップで拡大できる・送信状態の表示が出る、を見る。ケーブルが合わず無理なら、無理しない。
5. **コミットは SK-06 の2ファイルだけ。** 余計なファイルを入れない。`git add` は、ファイル名を指定して行う（`git add .` は使わない）。
6. **PRを出す。** PRの説明に次を書く。
   - 何を作ったか（1〜2行）
   - テスト: 成功した件数
   - 実機確認: 「済み」または「**実機: 未実施**（理由）」
7. **PRのURLを、Slackで大久保に伝える。**

## 守ること

- **範囲を増やさない。** 気になった改善は、PRの説明に「今回はやらないこと」として書く。
- 送信キュー（`queue/`）と設定（`settings/`）は触らない。そこは大久保の担当。
- 詰まったら、状況（どこまで進んだか・エラー文）を貼ってSlackで相談する。推測で大きく書き換えない。
- 実機を確認できなかったことは、隠さず「未実施」と書く。これは失敗ではない。
