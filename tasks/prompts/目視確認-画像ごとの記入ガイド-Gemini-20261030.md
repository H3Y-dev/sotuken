## 画像1枚あたりの流れ

### 手順A. 画像を開く
Googleドライブの画像フォルダで、その番号の画像を開き、必要なだけ拡大します。画像の色の意味は次のとおりです。
- 緑 = 正解（十字が中心、点が0点・満尺・針先、文字が正解の値）
- 赤 = プログラムの検出（十字が中心、点が0点・満尺、線が針）
- 青 = 検出した目盛り（T1, T2…の番号）
- 黄 = 読んだ数字（N1, N2…）

### 手順B. シートの該当タブを開く
「目視確認シート」の、画像と同じ番号のタブ（例: 003）を開きます。**書き込むのは H・I・J の3列だけ**です。

| 列 | 名前 | 書くか |
|---|---|---|
| A〜G | 段階・項目・検出した内容・位置・スコア・対応目盛り・範囲判定への使用 | **書かない**（プログラムの出力） |
| H | 人が読んだもの | **書く** |
| I | 合っているか(○×) | **書く**（判断できなければ「？」） |
| J | メモ | **書く**（気づきを自由に） |

### 各列の意味（AIは、本人に聞かれたら、この説明をそのまま使って教える）

**プログラムが入れた列（A〜G）。見るだけで、書き換えない。**

| 列 | 意味 | 見方 |
|---|---|---|
| A 段階 | プログラムの処理の段階（①中心 ②目盛り ③数字 ④範囲 ⑤針 ⑥値） | 上から順に処理が進む。どこで間違えたかを探すのが目的 |
| B 項目 | その段階の中の1項目（N1, N2…は読んだ数字の番号） | 画像の黄色いラベル N1, N2… と対応する |
| C 検出した内容 | **プログラムが出した答え** | ここが正しいかを、画像と見比べて確かめる |
| D 位置 | 画像の中の座標（x, y）。ピクセル単位 | 数値を確かめる必要はない。画像上の同じ番号のラベルを探す目印にする |
| E スコア | 数字を読んだときの自信（0〜1） | 参考。低くても正しいことがある。判断に使わない |
| F 対応目盛り | その数字に結びつけた目盛りの番号（T1, T2…） | 画像の青いラベル T○ と対応する。「なし」は目盛りに結びつかなかった |
| G 範囲判定への使用 | その数字を、メーターの範囲（0点と満尺）の根拠として使ったか。○=決まった範囲に合う数字で、目盛りにも結びついている、×=範囲に合わない、または目盛りに結びつかなかった、不明=範囲そのものが決まらなかった | プログラムの内部の記録。**○×を直さない。「×」は、数字が間違っているという意味ではない。人の判断はI列に書く** |

**人が書く列（H〜J）。**

| 列 | 書くこと | ルール |
|---|---|---|
| H 人が読んだもの | **自分の目で、画像から読んだ内容**。C列のコピーではない | C列を見る前に、画像だけで先に読んで書く（先入観を避ける）。数字は見えたとおり。読めなければ「読めない」 |
| I 合っているか | H列（人）とC列（プログラム）が**同じ内容か**。同じ=○、違う=×、判断できない=？ | 小数点以下の細かい違い（0.52 と 0.5 など）は○。意味が違えば×。**C列が「未検出」なら ×** |
| J メモ | 気づいたこと。**×や？のときは、理由を必ず書く** | 例は下の表。何が原因そうか（反射、ブレ、斜め、汚れ、紛らわしい文字、数字が小さい、針が隠れている）を一言でよい |

### 行ごとの書き方の例（数字は例。実際の画像のものに置き換える）

| 行 | C列（プログラム） | H列に書く例 | I列 | J列に書く例 |
|---|---|---|---|---|
| 中心座標 | (640.0, 480.0) | 軸と一致 | ○ | （空欄でよい） |
| 中心座標 | (604.0, 490.0) | 軸より右に約30px（画像の横幅の1/40） | × | 斜めから撮ったため、楕円の中心とずれた |
| 目盛り本数 | 主目盛り: 8本 | 数字付きの長い目盛りは9本 | × | 左端の1本が反射で見えず検出されていない |
| 数字 N2 | 61 | 51 | × | 5を6と読み違え。数字が小さい |
| 数字 N5 | 0 | 0 | ○ | |
| OCRが読まなかった数字 | - | 「100」が読まれていない | × | 右端の数字がガラスの反射で白く飛んでいる |
| 最小値・最大値 | 0〜121 | 0〜120 | × | 満尺が120なのに121と読んだ（N7の誤読が原因） |
| 針角度・針先 | 23.2度、針先 (449, 581) | 針は左下を指している。赤い線は針に乗っている | ○ | |
| 読み取り値 | 読んだ値: 0.00（正解 -10.2） | 針は「-20と0の間、約-10」を指す | × | 範囲が間違ったため、値も大きくずれた |

### 「一覧」タブの書き方

- J列「人の総合判定(○×)」: 針が目で見て指している値と、プログラムの「読んだ値」が近ければ ○（目安: 目盛り1〜2個分以内）、離れていれば ×。「誤差%FS」の列は参考にとどめる。
- K列「いちばんの原因」: 各タブで、**最初に ×が付いた段階**を選び、理由を一言で。例: 「③数字: 反射でN2を61と読んだ」「④範囲: 数字は合っているが0点の位置を間違えた」「①中心: 斜めでずれた」。すべて ○なのに最終値が違うときは「⑥値: 計算の問題の可能性」と書く。

### 手順C. 行ごとに埋める（上の行から順番に）

行ごとに、見る場所と書く内容が違います。AIは、次の表に従って1行ずつ案内してください。

| 行（A列の段階／B列の項目） | 画像のどこを見るか | H列「人が読んだもの」に書くこと | I列 ○× の基準 |
|---|---|---|---|
| 段階① 中心座標 | 赤い十字が、針の根元（針が回る軸）にあるか。緑の十字と比べる | 「軸と一致」「右に少しずれ」のように、ずれの向きと大きさ | 赤い十字が針の根元にあれば○ |
| 段階② 目盛り本数 | 青いT番号の線が、実際の目盛りの線に乗っているか | 目で見て、数字付きの長い目盛り（主目盛り）が何本あるか | プログラムの主目盛り数と同じなら○ |
| 段階③ N1, N2… | 黄色い数字N1、N2…の位置にある、実際の数字 | **その位置に実際に書いてある数字**（例: 「58に見える」「50」） | 読んだ数字（C列）が実際の数字と同じなら○ |
| 段階③ OCRが読まなかった目盛りの数字 | 数字が書いてあるのに黄色のNが付いていない場所 | 読まれなかった数字を書く（なければ「なし」） | 読み落としがなければ○、あれば× |
| 段階④ 最小値・最大値 | 赤い点（0点・満尺）の位置 | 目で見た「いちばん小さい目盛りの数字」と「いちばん大きい目盛りの数字」 | 検出した範囲（C列）と同じなら○ |
| 段階⑤ 針角度・針先 | 赤い線（針）と、緑の針先の点 | 針の先が指している目盛りの数字（例: 「50と60の間、少し60寄り」） | 赤い線が実際の針に乗っていれば○ |
| 段階⑥ 読み取り値 | 画像全体 | 針の指す値を目で読んだ数字（例: 「約53」） | 読んだ値（C列）とほぼ同じなら○ |

「止まった段階」が `scale`（範囲）や `center`（中心）の画像では、C列が「未検出」の行があります。その行は、H列に**自分が見て読んだもの**を書き、I列は「×」、J列に「プログラムは未検出」と書いてください。

### 手順D. 「一覧」タブを埋める
その画像の行を探して、次の2列だけ書きます。
- J列「人の総合判定(○×)」: 最終的な値が正しければ○、違えば×。
- K列「いちばんの原因」: 6つの段階（中心・目盛り・数字・範囲・針・値）のうち、**最初に間違えた段階**と理由を一言で。例: 「数字: 反射で58を50と読んだ」「範囲: 数字は合っているが0点を間違えた」

### 手順E. 次の画像へ
手順A〜Dを10枚分繰り返します。

## 全部終わったら

- 共通して起きていた問題

書いたら、大久保にSlackで「終わりました」と連絡します。

## 守ること

- **書いていいのは、各タブのH・I・J列と、「一覧」のJ・K列、まとめの行だけ。** ほかのセルは書き換えない。
- 分からないときは推測で埋めず「？」と書き、理由をメモ（J列）に書く。分からないことも大事な情報です。
- プログラムの修正はしない。改善案を思いついたら、メモに書くだけでよい。
- 詰まったら、状況（どの画像のどの行か）を文章にして大久保に相談する。

## AIへのお願い

- 本人が迷ったら、現在の画像番号、いまの行、次にやることを1つだけ示す。
- 本人が画像を貼ったら、緑と赤の違いを言葉で説明し、見る場所を案内する。答えを決めつけず、本人の判断を促す。
- H列に書く内容の例を、その行に合わせて1つ示す。
