# 5. 直すべき点(1): 絵文字が原因で実行が途中で止まる

`try_ocr.py` の中で `print()` に絵文字を使っている箇所があります(26, 58, 59, 60, 67, 84, 86, 101, 104行目、たとえば ❌📄🔄🔢💡🖼️⚠️🚀)。これが原因で、**Windows の日本語環境では実行が途中で必ず止まります。**

実際に実行すると、次のようなエラーが出るはずです。

```
UnicodeEncodeError: 'cp932' codec can't encode character '\U0001f680' in position 0: illegal multibyte sequence
```

## なぜ起きるか

Windows の日本語環境のコンソール（黒い画面）は、文字を `cp932` という古い文字コードで表示しています。この文字コードは日本語には対応していますが、🚀 のような絵文字には対応していません。「対応していない文字を表示しようとして、表示係（コンソール）がお手上げになって止まる」というイメージです。

## 直し方

難しい修正ではありません。絵文字を、意味の伝わる普通の文字に置き換えるだけです。たとえば:

| 元 | 直す例 |
|---|---|
| `❌ 画像読み込み失敗` | `[NG] 画像読み込み失敗` |
| `📄 ファイル名` | `[ファイル名]` |
| `🔄 判定された向き` | `[向き]` |
| `🔢 検出された数字` | `[検出数]` |
| `💡 認識された数値` | `[数値]` |
| `🖼️ 確認用画像を保存しました` | `[保存]` |
| `⚠️ 目盛り数字が検出できませんでした` | `[警告]` |
| `🚀 === 開始します ===` | `=== 開始します ===` |

これは「センスの問題」ではなく「Windowsのコンソールの仕様の問題」なので、直しても見た目が悪くなるわけではありません。気にせずどんどん置き換えて大丈夫です。

```python
import cv2
import scale_value_detect


def normalize_orientation(img):
    """
    画像を0度・90度・180度・270度回転させてOCRを試し、
    一番多く数字が読めた向きに直した画像を返す。

    引数:
        img: 判定したい画像（cv2で読み込んだもの）
    戻り値:
        向きを直した後の画像
    """
    best_angle = 0
    best_count = -1  # まだ何も試していない印

    angles = [0, 90, 180, 270]
    for angle in angles:
        rotated = _rotate(img, angle)
        results = scale_value_detect.read_scale_numbers(rotated)
        count = len(results)

        # 同点のときは0度を優先したいので > を使う（>= にしない）
        if count > best_count:
            best_count = count
            best_angle = angle

    return _rotate(img, best_angle)


def _rotate(img, angle):
    """画像を指定した角度だけ回転させる。0度はそのまま返す。"""
    if angle == 0:
        return img
    elif angle == 90:
        return cv2.rotate(img, cv2.ROTATE_90_CLOCKWISE)
    elif angle == 180:
        return cv2.rotate(img, cv2.ROTATE_180)
    elif angle == 270:
        return cv2.rotate(img, cv2.ROTATE_90_COUNTERCLOCKWISE)
```

## ステップB: 比較ログを分かりやすくする

現状の `try_ocr.py` は、一番良かった向きの結果しか表示していません。「0度のときは何個読めたか」が分からないので、**改善したことが数字で示せていません。** ここを直します。

### やること

`normalize_orientation` を使う側（`try_ocr.py` の `process_meter_image`）で、**0度のときの個数** と **採用した向きのときの個数** を両方表示するようにします。次のような出力を目指します。

```
[結果] 20260817_134606.jpg : 0度 3個 → 90度 12個 に採用（+9）
```

### 考え方

`normalize_orientation` は今、「一番良い向きの画像」だけを返す設計です。ログに0度の個数も出したい場合、関数の戻り値を増やすか、ログ用に別の情報を返す関数を分けるか、という選択が出てきます。たとえば次のように、**戻り値をタプル(複数の値をまとめて返す書き方)にする** のが一つの案です。

```python
def normalize_orientation(img):
    """
    戻り値: (向きを直した画像, 採用した角度, 採用した角度でのOCR検出数, 0度での検出数)
    """
    best_angle = 0
    best_count = -1
    zero_count = 0

    angles = [0, 90, 180, 270]
    for angle in angles:
        rotated = _rotate(img, angle)
        count = len(scale_value_detect.read_scale_numbers(rotated))

        if angle == 0:
            zero_count = count

        if count > best_count:
            best_count = count
            best_angle = angle

    return _rotate(img, best_angle), best_angle, best_count, zero_count
```

呼び出し側はこう変わります。

```python
fixed_img, angle, count, zero_count = orientation.normalize_orientation(img)
print(f"[結果] {filename} : 0度 {zero_count}個 -> {angle}度 {count}個 に採用")
```

**これは一つの案です。** 「戻り値が4つもあると使いにくくないか」とYMさんが感じたら、それは良い気づきです。辞書(dict)にまとめて1つ返す案もあります。どちらでも受け入れ条件は満たせるので、好きな方を選んでもらって構いません。

### 進め方

- 直したら、実際に画像を数枚読み込んで、「0度→90度で個数が増えている」ことが目で見えるログを出してもらってください。ここが今回のタスクで一番「効果が見える」瞬間です。増えていたら具体的に褒めてください（例:「0度で3個だったのが90度で12個読めています。9個増えました」）。
- 終わったらコミット。例: `向き判定の前後比較をログに出力`

# 12. 想定される質問への答え（先回りして用意しておいてください）

**Q. なぜ絵文字がダメなんですか？普通に動いてましたよ？**
A. 環境によって動いたり動かなかったりする、という点がまさに問題です。開発環境（エディタの中の実行など）では表示できても、Windowsの標準コンソール（黒い画面、文字コードcp932）では表示できません。チームメイトが別のPCで実行したときに突然止まる、という一番厄介な形で問題が起きます。`[OK]` `[NG]` のような普通の文字なら、どの環境でも確実に動きます。

**Q. 「関数にする」って、具体的に何が変わるんですか？**
A. 今の `try_ocr.py` は「実行したら画面に結果を表示して終わり」のスクリプトです。関数 `normalize_orientation(img)` にすると、**画像を渡せば、直した画像を返してくれる部品** になります。この先、チームの他の人が書く本番のパイプライン（`meter_pipeline.py` など）から、YMさんの向き判定を「部品として呼び出せる」ようになります。表示するだけでは、他の人のコードから使えません。

**Q. 戻り値を4つも返すのは変な感じがします。**
A. 良い感覚です。戻り値が増えすぎると使いにくくなるのは事実です。「画像を返す関数」と「ログ用の情報を返す関数」を分ける、辞書1つにまとめて返す、など複数のやり方があります。正解は1つではないので、使う側（`try_ocr.py`）で書きやすい形をYMさん自身に選んでもらってください。

**Q. テストって何のために書くんですか？もう動いているのに。**
A. 「今動いている」ことと「ずっと動き続ける」ことは別です。この先、他の人が `scale_value_detect.py` や `orientation.py` を触ったときに、気づかないうちに向き判定が壊れることがあります。テストがあれば、`venv\Scripts\python.exe -m unittest discover -s tests` を実行するだけで「壊れていないか」がすぐ分かります。一度書けば、その後は書いた本人が何度も手で確認しなくて済むようになる、という自分のための保険でもあります。

**Q. 13枚全部でテストしなくていいんですか？**
A. `tests/test_orientation.py` の自動テストは1〜2枚で十分です（OCRが重く、毎回13枚回すと遅すぎます）。13枚全部を使うのは「効果を測る」ための別の作業（完成の定義のチェックリストにある「前→後の表」）で、これは自動テストとは別に一度実行して結果を記録すれば十分です。
