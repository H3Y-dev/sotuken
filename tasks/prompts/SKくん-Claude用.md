## 1. プロジェクトの背景

### 何を作っているのか

工場のアナログメーター（電流計・温度計など）を**スマホ等で撮影するだけで**、針の指す値を自動で読み取り、データ化して一元管理するシステムを作っています。**日本製鋼所様との共同研究**で、卒業までの完成が目標です。

現場では今、点検員がメーターを目視して紙やExcelに転記しています。この転記作業をなくすのが最終的な狙いです。「撮影 → 読み取り → 記録 → 一覧」が通しで動くところまでが完成形で、現在は「読み取り」の精度を上げている段階です。

### 現在のパイプライン

1画像1メーターを前提に、次の順で処理しています。

```
VLM(Qwen3-VL)で盤面をクロップ
  → Hough円検出で回転中心を推定
  → PCAベースで目盛り線を検出（数十本）
  → RapidOCRで目盛りの数値を読み取り、目盛り線に対応付け
  → Hough変換で針を検出
  → 針の角度を線形に按分して値を算出   ← ここがSKくんの担当箇所
```

### 精度の測り方（チーム共通の言語）

主指標は **引用誤差 [%FS]** です。定義は次のとおりで、`evaluate.py` の `reference_error()` に実装されています。

```
引用誤差[%FS] = |読取値 − 真値| / |val_max − val_min| × 100
```

相対誤差（真値で割る）ではなく引用誤差を使うのは、真値が0付近だと相対誤差が発散して比較できなくなるためです。また、計器の確度階級（**JIS C 1102 の 2.5級 = ±2.5%FS**）もフルスケール基準で定義されているので、そのまま合否判定に使えます。合格ラインはこの ±2.5%FS です。

なお、人の補助なしの現状の実力は**引用誤差 37%FS** です。目標との差は大きく、SKくんのタスクはその差を詰める複数トラックのうちの1つです。

5人で並行開発しており、**ファイルの担当を分けることで衝突を避ける**方針です。他メンバーが同時に別のファイルを触っています。詳細は `tasks/plan.md` と `tasks/todo.md` にあります。

## 2. SKくんの担当タスク: T2 非線形スケール対応

### 何が問題なのか

`meter_reader.py` の現行実装は、**目盛りの「ゼロ点」と「フルスケール点」の2点だけ**を使って値を出しています。

```python
ratio = arc_ratio(theta_needle, theta_zero, theta_full)   # 弧上の位置を 0.0〜1.0 で
value = ratio_to_value(ratio, val_min, val_max)           # val_min + ratio * (val_max - val_min)
```

つまり「角度に対して目盛りが等間隔に並んでいる（線形スケール）」ことを前提にしています。`ratio_to_value` の docstring にもその旨が明記されています。

しかし対象の電流計は **可動鉄片形**です。可動鉄片形は駆動トルクが電流の**2乗に比例**するため、素の目盛りは低い側ほど詰まった非線形スケールになります。実際の計器は鉄片の形状を工夫して上側80〜90%をほぼ等分に近づけていますが、**下側20%程度には非線形性がはっきり残ります**。

その結果、両端2点の線形按分では**中間域（特に低い側）に系統誤差**が乗ります。ランダムな誤差ではなく、常に同じ向きに外れる誤差です。

そして最大の無駄は、**パイプラインは既に目盛り線を数十本検出しており、OCRで値が対応付いた目盛りも複数あるのに、値の算出には両端2点しか使っていない**ことです。持っている情報を捨てています。

### 何を作るのか

OCRで値が対応付いた目盛りを**全部使って**、角度 → 値の**単調な補間関数**を作ります。

インターフェースはチームで既に合意済み（T0-2）なので、**シグネチャは変えないでください**。

```python
calibration = [(angle_rad, value), ...]   # 角度順にソート済み、2点以上
def value_from_angle(theta, calibration):
    """単調補間して値を返す"""
```

## 3. 技術的に外してはいけない点

ここが今回の実装の核心です。SKくんと一緒に、着手前にこの節の内容を確認してください。

### 3-1. 「較正点が2点のとき現行の線形補間と完全に一致する」の意味

これは受け入れ条件の中で**唯一の絶対条件**です。過去の検出ログ24件を再現する回帰テスト（`tests/test_regression_logs.py`）がこれを担保しており、ここが崩れると「精度改善のはずが過去の正解を壊した」ことになります。

数学的には、区分線形補間の節点が2つ = 区間が1つなので、それは単一の線形関数そのものです。**一致すること自体は自明**です。落とし穴は補間ではなく、**角度のパラメータ化**にあります。

- `math.atan2` が返す角度は `(-π, π]` の範囲です。
- したがって素朴に `(theta - theta_zero) / (theta_full - theta_zero)` と書くと、**弧が ±π をまたぐメーターで破綻**します。例えばゼロ点が135°、フルスケール点が−135°（=225°）のメーターでは、この式の分母が負になり、弧の外を指しているように見えてしまいます。
- 既存の `arc_ratio` は、これを **mod 2π と回転方向（時計回り／反時計回り）の推定**で吸収しています。両方向で比率を計算し、0〜1に収まる方を採用し、両方収まる場合は弧が長い側を採る、という実装です。`tests/test_meter_reader.py` の `test_arc_crossing_the_180_degree_boundary` がまさにこのケースを固定しています。

**したがって「完全一致」の必要十分条件は、同じ弧位置 `r` を使うことです。** 生の atan2 の値に対して `numpy.interp` をかけると、この吸収が消えるので一致しません。

さらに浮動小数点レベルまで揃えるなら、**式の形も揃えてください**。現行は `val_min + ratio * (val_max - val_min)` です。`numpy.interp` は内部の式が異なるため、最下位ビットがずれる可能性があります（回帰テストは `places=3` なので実害は出ませんが、受け入れ条件が「完全に一致」なので、`v0 + t * (v1 - v0)` の形に揃えておくのが安全です）。

**最も確実な実装方針:**

```
較正点が2点のときは、arc_ratio() + ratio_to_value() にそのまま委譲する。
3点以上のときだけ、新しい補間経路に入る。
```

これなら一致は実装レベルで自明に保証されます。特別扱いに見えますが、「既存の挙動を壊さない」という制約を証明可能な形で満たすほうが優先です。

### 3-2. 3点以上のときの弧位置の求め方

各較正点を弧上の位置 `u` に写してから補間します。ここで**`arc_ratio` を各点に対して個別に呼ぶのは避けてください**。`arc_ratio` は「0〜1に収まる方の向きを採る」という点ごとの判定を含むため、弧の外に出た点で向きが反転しうるからです。

正しくは、**向きは端点だけから一度決めて、全ての点に同じ向きを適用**します。

```
span_cw  = (theta_full - theta_zero) mod 2π
span_ccw = (theta_zero - theta_full) mod 2π
（向きの判定順序は arc_ratio と揃える）

時計回りなら:   u_i = ((theta_i - theta_zero) mod 2π) / span_cw
反時計回りなら: u_i = ((theta_zero - theta_i) mod 2π) / span_ccw
```

この段階では `u_i` が `[0, 1]` の外に出ることを**許してください**。範囲外に出る点は「弧の外を指す較正点」であり、後段の外れ値除去にとって重要な手がかりになります。ここで早まってクランプすると、誤読の証拠を消してしまいます。

なお、インターフェースの契約では calibration は「角度順にソート済み」ですが、**±π をまたぐ場合に atan2 の値でソートすると弧に沿った順序と一致しません**（例: 弧の順序が 135° → 180° → −135° なのに、atan2 値でソートすると −135° → 135° → 180° になる）。呼び出し側を信用しきらず、内部で `u` に写してからその昇順に並べ直してください。シグネチャは変えず、堅牢性だけ内部で確保します。

### 3-3. 「単調」の2つの意味を区別する

混同しやすいので、必ず分けて考えてください。

**(a) データの単調性** — 較正点そのものが単調か。`u` の昇順に並べたとき、値 `v` が単調増加（またはメーターの向きによっては単調減少）になっているか。OCRの誤読が混ざるとここが崩れます。

**(b) 補間関数の単調性** — 作った関数 `f` が `u1 < u2 ⟹ f(u1) ≤ f(u2)` を満たすか。**節点データが単調でも、補間手法によっては関数が単調にならない**ことが重要です。

補間手法の選択肢とトレードオフ:

| 手法 | 単調性 | 滑らかさ | 依存 | 評価 |
|---|---|---|---|---|
| **区分線形** | データが単調なら**必ず**単調（各区間の傾きが同符号になるため） | C0のみ。節点で折れる | 不要 | **まずこれで実装する** |
| **PCHIP**（Fritsch–Carlson の単調3次エルミート） | **保証あり** | C1（1階微分連続、2階は不連続） | scipy または自前50行程度 | 区分線形で精度が足りないときの次の一手 |
| 自然3次スプライン | **保証なし** | C2 | scipy | **使わない** |
| 単調回帰（PAVA / isotonic） | 保証あり | — | — | 用途が違う（下記） |

**自然3次スプラインを使ってはいけない理由**を明確にしておきます。自然3次スプラインは節点で2階微分まで連続にする代わりに、節点間でオーバーシュート（行き過ぎ）や振動を起こします。その結果、**ある目盛りとその隣の目盛りの間で、両方の目盛り値より小さい（または大きい）値を返しうる**のです。「針が目盛り3と目盛り4の間にあるのに、読み取り値が2.8になる」という物理的にありえない出力になります。単調性が保証されない補間はこの用途では不合格です。

**PCHIP が単調を保証する仕組み** も押さえておいてください。区間ごとの割線傾き `Δ_i = (v_{i+1} - v_i) / (u_{i+1} - u_i)` に対して、節点での導関数 `d_i` を「隣接する割線傾きの重み付き調和平均」で決め、`Δ_{i-1}` と `Δ_i` の符号が異なる（またはどちらかが0）ときは `d_i = 0` とします。これにより Fritsch–Carlson の単調条件（簡便な十分条件としては `0 ≤ d_i ≤ 3·min(|Δ_{i-1}|, |Δ_i|)` を符号込みで満たすこと）が成立し、区間内に極値が生じません。**節点が2つのときは `d_0 = d_1 = Δ_0` となって3次多項式が線形に退化する**ので、PCHIP を採用しても3-1の「2点で線形一致」は保たれます。

**どちらを選ぶかの判断基準:** 区分線形の補間誤差は `max|v''| · h² / 8` のオーダーです（`h` は節点間隔）。目盛り線が数十本検出できていれば `h` は数度程度まで小さくなり、この誤差は %FS で見て無視できる可能性が高いです。**まず区分線形で実装して評価基盤の数値を出し、それでも足りない場合にだけ PCHIP に進んでください。** 最初から凝った手法を選ぶのは、複雑さを増やして得られるものが小さい典型例です。

**単調回帰（PAVA）は用途が違います。** これは「外れ値を落とす」手法ではなく、「与えられた列に最小二乗の意味で最も近い単調列に潰す」手法です。誤読が少数の場合は、潰すより除去するほうが素直です。

### 3-4. 外れ値の除去

OCRの誤読は、**単発で大きく外れる**のが特徴です。典型的には `0 → 8`、`6 → 5`、小数点落ち（`1.5 → 15`）、`10 → 40` のような誤りです。

方針の候補:

- **端点（ゼロ点・フルスケール点）をアンカーとして扱う。** この2点は現行パイプライン（`scale_value_detect.py`）がクロスチェックとVLM照合まで行って決めている、最も検証された点です。他の点より信頼度が高いと見なして構いません。
- **`u` 順に並べた値列の最長単調増加部分列（LIS）を取る。** O(n log n) で、単発の誤読に強い手法です。ただし複数点が同じ方向に誤っている場合は効きません。
- **端点を結ぶ直線からの残差で切る。** ただし対象は非線形スケールなので、閾値は緩めに、かつ **%FS 単位**（値の絶対量ではなくフルスケール比）で設定してください。単位が混ざるとメーターのレンジが変わるたびに閾値が意味を失います。
- **`u` が重複、または極端に近い点は片方を捨てる。** 区間幅が0になるとゼロ除算します。ここは必ず入れてください。
- **値が単調減少するスケールもありうる**（値が右から左に増える配置）ことを想定してください。`u` の取り方で大半は吸収されますが、`v` が減少列の場合も扱えるようにします。

**除去後の縮退時の挙動が重要です。** 外れ値を落とした結果、残りが2点未満になったら、**端点だけを使った現行動作にフォールバックしてください。例外を投げてはいけません。** このコードは自動評価パイプラインの中で数十枚の画像に対して回ります。1枚の異常で全体が止まるのは、精度以前の問題です。

`compute_reading()` に **デフォルト `None` のキーワード引数** を1つ足すのが最小の接続です。


`calibration=None` のときは現行と完全に同じ経路を通るので、`meter_pipeline.py`（触ってはいけないファイル）を1行も変えずに済みます。較正点を実際に供給する側は別トラック（T3 / `scale_value_detect.py`）の担当なので、**SKくんは「関数を作って、受け口を用意する」ところまでが範囲**です。供給側の完成を待つ必要はありません。

- **`ratio_to_value()` は消さないでください。** 既存テスト（`TestRatioToValue`）が直接呼んでおり、`compute_reading()` の内部でも使われています。GUI（`main_sotuken.py`）と評価基盤は `compute_reading()` 経由でここに到達します。

- 戻り値は素の Python `float` に揃えてください（`np.float64` は `float` のサブクラスなので実害はありませんが、型が混ざると後段が読みにくくなります）。

## 5. ガイドライン

1. **テストを先に書く。** 今回は画像に依存しない純粋な数値計算なので、TDDが最も素直に効くタスクです。合成データで期待値を作れるため、実装前に受け入れ条件をテストに落とせます。
2. **既存の挙動を壊さない。** 変更のたびに全テストを回してください。特に `tests/test_regression_logs.py`（過去ログ24件）と `TestArcRatio` / `TestRatioToValue` は現行の正解を固定しているものです。
3. **触ってはいけないファイルを触らない。**（2節のリスト）
4. **単位と指標を混ぜない。** 誤差の議論は原則 **%FS**（フルスケール比）で行ってください。「誤差0.3」では、レンジが 0〜5A なのか 0〜50A なのかで意味が変わります。

6. **例外を投げて止めない。** 異常な入力は縮退動作で吸収します（3-4参照）。

## 9. SKくんから出そうな質問への回答（先回り）

**Q. scipy を使っていいですか？ `scipy.interpolate.PchipInterpolator` があるはずですが。**
A. venv には scipy 1.10.1 が入っていますが、**`requirements.txt` には記載がありません**。つまり他のメンバーの環境や、今後のクリーンな環境では入っていない可能性があります。「追加依存を増やさない」がリポジトリの方針なので、まずは numpy と標準ライブラリだけで実装してください。PCHIP がどうしても必要になった場合は、Fritsch–Carlson の導関数決定を自前で書けば50行程度です（3-3参照）。それでも scipy を使いたい場合は、`requirements.txt` への追記を含めてチームに諮ってください。

**Q. pytest で書いていいですか？**
A. 入っていません。**標準の unittest** を使ってください。既存の `tests/test_meter_reader.py` と同じスタイル（`unittest.TestCase` を継承、複数ケースは `subTest` で回す）に合わせます。

**Q. 較正点は誰が用意するんですか？ 今は両端2点しか来ませんが。**
A. 供給側は別トラック（T3 / `scale_value_detect.py`）の担当で、そのファイルは触ってはいけないリストに入っています。**SKくんの範囲は「補間関数を作って、`compute_reading` に受け口を用意する」まで**です。供給側の完成を待たずに進められるよう、そう分割されています。テストは合成データで書けます。

**Q. `ratio_to_value` は消してもいいですか？ 役目が終わったように見えますが。**
A. 消さないでください。既存テスト（`TestRatioToValue`）が直接呼んでおり、`compute_reading()` の内部でも使われています。GUI（`main_sotuken.py`、触ってはいけないファイル）と評価基盤は `compute_reading()` 経由でここに依存しています。新しい関数は**追加**であって置き換えではありません。

**Q. 回帰テストが「スキップ」と出ました。**
A. `logs/` は git 管理外なので、ログが手元に無い環境ではスキップされます。**スキップは「通った」ではありません。** ログがあるかを確認し、無ければチーム（本人）に共有を依頼してください。回帰テストが実際に走らない状態では、「2点で完全一致」の担保が効いていません。

**Q. 引用誤差はどう計算するんですか？**
A. `|読取値 − 真値| / |val_max − val_min| × 100` です。`evaluate.py` の `reference_error()` に実装があります。合格ラインは JIS C 1102 2.5級の **±2.5%FS**。

**Q. 角度の向きは？ y軸が下向きだと符号が変わりませんか？**
A. 画像座標系なので y は下向き正です。`atan2(dy, dx)` の結果はその座標系での角度になります。**時計回りか反時計回りかは事前に決められない**ので、`arc_ratio` が端点から推定しています。この推定ロジックを再実装せず、そのまま利用する設計にしてください（3-2）。

**Q. 目盛りが数十本あるなら、区分線形で十分では？ わざわざ PCHIP を書く意味は？**
A. その通りで、**まず区分線形で評価基盤の数値を出すのが正解**です。節点間隔 `h` が小さければ区分線形の誤差は `max|v''|·h²/8` のオーダーで、%FS 単位では無視できる可能性が高い。PCHIP は「区分線形で目標に届かなかったとき」の次の手であって、最初の一手ではありません。

**Q. 外れ値の閾値はいくつにすればいいですか？**
A. 数値を先に決めるのではなく、**%FS 単位で決めてください**。絶対値で決めるとメーターのレンジが変わるたびに意味が変わります。具体的な値は、合成データと実データの両方で残差の分布を見てから決めるのが順序です。決め打ちの前に一度分布を出しましょう。

**Q. どこまでやったら「終わり」ですか？**
A. 6節のチェックリストが全部埋まったときです。特に最後の2つ（回帰テストが**実際に走って**通る／評価基盤の数値が悪化していない）が実質的なゲートです。
