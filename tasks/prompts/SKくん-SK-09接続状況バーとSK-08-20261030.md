## 1. SK-09 接続状況バー ＋ 履歴の送信理由（PR 1つ目）

最新のmainから `feat/sk-09-connection-bar` を作って始めます（`git switch main` → `git pull` → `git switch -c feat/sk-09-connection-bar`）。

**やること**（詳細は設計メモ）:
1. メイン画面の一番上に、1行の色つきの帯を足す。状態は4つ（送信先が未設定・確認中・接続中・届かない）。**接続中**は「未着 N件」と「最終送信 HH:mm」も出す。**届かない**は、理由（接続できません／合言葉が違います／送信先の形式が違います／応答がありません）も出す。
2. 疎通確認は、`HttpSender.health(url, token)`（`queue/sender/HttpSender.kt`の`companion object`の関数。`Result<Unit>`を返す）を使う。**同期の関数なので、`Dispatchers.IO` で呼ぶ**（メインスレッドで呼ぶと、画面が固まる）。タイミングは、起動時、ON_RESUME、15秒ごと（画面が見えている間だけ）、送信先の設定を保存した直後、撮影の直後。
3. 「未着 N件」と「最終送信」は、キューの項目（`QueueItem`）から数える。`sendState`が`PENDING`・`SENDING`・`FAILED`の件数 ＋ `SENT`で`sentVia == QueueItem.VIA_FOLDER`の件数が「未着」。「最終送信」は`sentVia == VIA_HTTP`の項目の`sentAt`の最新。
4. 帯をタップすると、小さなダイアログで詳細を出す（PCのURL、最終送信、未着、直近の失敗の理由）。**合言葉は出さない。** 送信先が未設定のときは、タップで、既存の送信先の設定ダイアログを開く。
5. 履歴画面（`QueueListScreen.kt`）で、`SENT`かつ`sentVia == VIA_FOLDER`かつ`lastError`がある項目に、理由を小さな文字で出す（「PCに届かず、送信箱に保存: 接続できません」のように短く）。

**守ること**:
- **`queue/` と `settings/` は、読むだけ。書き換えない。**（大久保が管理しているパッケージです。足りないものがあれば、変えずに相談する。）
- 文言の整形・件数の計算・理由の分類・`HH:mm`の整形は、**関数に切り出して、単体テストを書く**（画面から切り離す）。
- 疎通確認で、撮影の操作が遅くならないこと。実機で、撮影を連続して、引っかかりがないか確かめる。

**検証**:
- `gradlew test --rerun-tasks` と `assembleDebug` を実行し、件数と結果を記録する。**debugとreleaseの両方のテストが数えられるので、合計は倍になります**（いまのmainで126件）。件数がこれと違っても、増えた分が新しいテストなら問題ありません。
- 実機で、(a) PCと同じWi-Fi・PCの`run_pc.py`を起動→**緑**、(b) PCのプログラムを止める、またはWi-Fiを切る→**黄**（理由が出る）、(c) 送信先の設定を空にする→**赤**、を目視する。PCが用意できなければ「未確認」と書く。履歴画面で、送信箱経由の項目に理由が出ることも目視する。

終わったらPRを出して**止まります**（マージは大久保）。PRの説明に、変えたファイル、テストの件数、実機確認の結果（済み／未実施）を書く。
