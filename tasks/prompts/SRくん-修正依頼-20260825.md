## 1. 見つかった問題（実行して確認済み）

### 問題(1): `manager/test_manager.py`に、解決していないgitのコンフリクトマーカーがそのまま残っている

実際に実行すると、ファイルの1行目でこうなります。

```
File "manager\test_manager.py", line 1
    <<<<<<< HEAD
    ^
SyntaxError: invalid syntax
```

`<<<<<<< HEAD` / `=======` / `>>>>>>> 4fe4497...` という記号がファイルの中にそのまま残っています。これは、ブランチをマージ（または過去のコミットを取り込む操作）したときに衝突が起き、**衝突をどちらの内容にするか選ばずに、そのままコミットしてしまった**状態です。中身を見ると、コンフリクトの片側（`<<<<<<< HEAD`から`=======`まで）に`manager.py`のクラス定義がまるごと紛れ込んでおり、本来の`test_manager.py`のテストコードは`=======`より下側に残っています。

**直し方:** `manager/test_manager.py`を開き、`<<<<<<< HEAD`から`=======`の直前までの塊（`manager.py`のクラス定義が入っている部分）を丸ごと削除し、`=======`と`>>>>>>> ...`の行自体も削除してください。残るのは、本来のテストコード（`import os` から始まる、`unittest.TestCase`を使ったテスト）だけになるはずです。

### 問題(2): `manager/manager.py`のimportの書き方が、既存のテストファイルと矛盾している

`manager/manager.py`の先頭が、以前は

```python
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from storage import MeterReading, Storage
```

だったのが、今回

```python
from manager.storage import MeterReading, Storage
```

に変わっています。これ単体は間違いではなく、`main.py`（リポジトリの一番上の階層にある）から`from manager.manager import MeterManager`と呼ぶ分には問題なく動きます。

ところが、`manager/test_integration.py`は今も

```python
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from manager import MeterManager
```

という**古い書き方のまま**です。これは「`manager`フォルダ自身をPythonの検索パスに追加してから、そこにある`manager.py`を`manager`という名前で読み込む」という意味です。ところが`manager.py`の中身が今は`from manager.storage import ...`（`manager`というパッケージ経由で`storage`を読み込む前提）になっているため、`test_integration.py`経由で読み込まれた瞬間に矛盾が起き、次のエラーになります。

```
ModuleNotFoundError: No module named 'manager.storage'; 'manager' is not a package
```

**直し方（推奨）:** `manager/manager.py`の先頭を、**元の書き方に戻してください。**

```python
import os
import sys

sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))

from storage import MeterReading, Storage
```

こう書くと、「`manager.py`自身が置かれているフォルダを検索パスに追加してから、`storage`を平置きの名前で読み込む」という動きになります。この書き方なら、次の**どちらの呼び出し方でも**問題なく動きます。

- `venv\Scripts\python.exe -m unittest discover -s manager -p "test_*.py"`（`tasks/todo.md`にある、これまでのテストの実行コマンド）
- `main.py`から`from manager.manager import MeterManager`で読み込む場合

**`from manager.storage import ...`という書き方自体が悪いわけではありません。** ただ、それを使うなら`test_integration.py`側の書き方も合わせて変える必要があり、今回はそこが揃っていなかったために壊れました。上記の「元に戻す」方法が一番影響範囲が小さく安全なので、まずはこちらを推奨します。

### 問題(3): `manager.db`と`readings_export.csv`がgitにコミットされている

```
manager.db               | Bin 0 -> 12288 bytes
readings_export.csv      |   1 +
```

これは実行時に生成される**データファイル**です。以前「`manager`配下のDBファイルや出力CSVはコミットしないのが原則」とチームで合意した通り、これらはgit管理から外す必要があります。

**直し方:**

```powershell

```

（`--cached`を付けると、手元のファイル自体は消さずに、gitの追跡対象からだけ外せます。）

次に、`.gitignore`に以下の2行を追加してください。

```
manager.db
readings_export.csv
```

### 残りステップB: 同じ写真を二重に取り込まない

同じフォルダを何度も処理したときに、同じ画像が2回記録されてしまう問題です。シンプルな対策案:

- 処理が終わった画像を`manager/processed/`のような別フォルダに移動する（一番簡単）
