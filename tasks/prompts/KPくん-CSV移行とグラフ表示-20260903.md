## 1. 今回やること：KP-03（2つあります）

### KP-03-a: `export_to_csv` を新スキーマへ移行し、互換プロパティを外す

**前回の移行には、意図的に残した穴が1つあります。** `manager/export.py` の `export_to_csv` が、まだ旧スキーマのままです。

```python
writer.writerow([r.id, r.timestamp, r.device_name, r.value, r.stage, r.image_path])
```

`r.id` と `r.timestamp` は旧スキーマの名前です。**前回、`tests/test_export.py` の `DummyReading` に互換の `@property` を足してテストを通しました。**

```python
@property
def id(self):
    return self.reading_id

@property
def timestamp(self):
    return self.captured_at
```

**これが問題です。この互換プロパティが、`export_to_csv` の破綻をテスト上で隠しています。** YMさんが作る本物のレコードクラスは `captured_at` を持ち `timestamp` を持たないので、**そのクラスを渡した瞬間に `export_to_csv` は `AttributeError` で落ちます。** テストは緑のままなので、気づくのは結合したときです。

やること。

1. `export_to_csv` を新スキーマへ移行する（`r.reading_id` と `r.captured_at` を使う）
2. **`DummyReading` から `id` と `timestamp` の互換 `@property` を削除する**
3. CSVのヘッダー行も新しい項目名に合わせる。**日本語のヘッダーは残して構いません**（Excelで開いたときに読みやすいので）。`utf-8-sig` での出力も維持してください
4. 削除したことでテストが落ちたら、**そのテストが旧スキーマに依存していた証拠**です。テスト側を新スキーマへ直してください

**互換プロパティを消したときに落ちるテストがあれば、それが今回いちばん価値のある発見です。** 落ちた箇所を日報に書いてください。

### KP-03-b: `app.py` にグラフを表示する

`app.py` はStreamlitの画面で、`tab1`（画像解析）と `tab2`（履歴確認・CSV出力）の2つのタブがあります。**`tab2` にグラフを追加してください。**

`manager/export.py` に、そのための関数が既にそろっています。

- `group_by_device(readings)` — 記録を機器名ごとの辞書にまとめる
- `readings_to_series(readings)` — 1機器分の記録を「撮影日時 → 値」の辞書にする（`value` が `None` の失敗記録は除外される）

やること。

1. `tab2` に「機器を選ぶ」プルダウンを置く。選択肢は `group_by_device` の結果のキー（機器名）
2. 選ばれた機器の記録を `readings_to_series` に通し、**時系列の折れ線グラフ**として表示する。`st.line_chart` を使うのが簡単です
3. **記録が0件のとき、値がすべて失敗（`None`）のときに、エラーにならず「表示できるデータがありません」と出す**

**注意点。**

- `readings_to_series` は辞書を返します。`st.line_chart` に渡すには `pandas` のSeriesかDataFrameへ変換してください。`app.py` は既に `pandas` を `pd` としてimportしています
- 日時は文字列で入っています。**そのまま並べると文字列順になります。** 時系列として正しく並ぶように、`pd.to_datetime` で変換してから並べ替えてください
- **絵文字は `app.py` の既存コードで使われていますが、これはStreamlitの画面表示用なので触らないでください。** 新しく `print()` を書くときは絵文字を使わないでください（cp932でエラーになります）

## 8. 最後に必ずやること：日報を書く

今回の作業が終わったら（途中で終わった場合も含めて）、日報をMarkdownファイル1枚にまとめてください。
ファイル名は `日報_<名前>_<YYYYMMDD>.md` です。書く内容は次の8項目です。
**分からない項目は「なし」と書き、空欄にしないでください。**

1. **名前と日付**
2. **今日のタスク名**（タスクIDを付ける。例: KP-03 CSV出力の新スキーマ移行とグラフ表示）
3. **やったこと** — 実際に手を動かした内容を3〜5行で。やろうとしたが着手できなかったことは、そう書く
4. **成果物** — 作成・変更したファイルのパス。コミットしたなら**コミットのハッシュ（先頭7文字）と
   ブランチ名**も書く。コミットしていないなら「未コミット」と書く
5. **テスト結果** — 実行したコマンドと、何件中何件パスしたか。実行していないなら「未実行」と、その理由
6. **受け入れ条件の達成状況** — 渡された受け入れ条件を1つずつ書き出し、達成／未達成を付ける
7. **詰まったところ・分からなかったこと** — **ここが一番大事です。** 解決できなかった点、判断に迷った点、
   推測で進めた箇所を正直に書いてください。「特になし」で済ませず、少しでも自信のない箇所は書き出してください
8. **次に必要なこと** — 次回やること、または大久保に判断・確認してほしいこと

**互換プロパティを消して落ちたテストがあれば、7に必ず書いてください。**

### 日報を書くときの注意

- **できなかったことを隠さないでください。** 進捗が無かった日も、どこで止まったかが分かれば次の手を打てます。
  うまくいったように書かれるのが一番困ります
- **推測で断定しないでください。** 確認していないことは「未確認」と書いてください
- 企業提供画像そのものや、その内容が分かる記述を日報に含めないでください
- 絵文字は使わないでください（Windowsのcp932で文字化けします）
