## 1. 本題: SK-07 機器名と真値の入力フォーム

最新mainから新しいブランチ `feat/sk-07-input-form` を作って始める（`git switch main` → `git pull` → `git switch -c feat/sk-07-input-form`）。衝突が出たら自分で直さず `git status` の出力を大久保へ送る。

**なぜ必要か:** 現場で何台も続けて撮ると、PCの一覧で「どの写真がどのメーターか」が分からなくなります。撮るときに機器名（例: ボイラー室の圧力計A-101）を選べれば、一覧でそのまま区別できます。真値（その場で人が目で読んだ値）を入れておくと、PC側の読み取り精度をあとで確かめる正解になります。

**今のコード:** `ui/MeterCaptureApp.kt` の100〜110行目付近（`queueStore.enqueue(` の呼び出し）で、撮影後に `queueStore.enqueue(...)` を呼ぶとき、`CaptureMeta(deviceName = null, operatorValue = null, operatorNote = null)` と**常にnullを渡しています。** ここに入力値を渡せるようにするのが今回の作業です。送信側（`queue/sender/SenderPayloads.kt`）は `device_name`・`operator_value` をすでにPCへ送る作りなので、送信側は変えなくてよいです。

受け入れ条件（`tasks/plan-android-sprints.md` のSK-07）:
- [ ] 機器名・真値の入力値がキューのメタデータへ渡る
- [ ] 両方を未入力にしても撮影からenqueueまで完了する
- [ ] 過去に入力した機器名を候補として表示し、選んで入力できる（候補は端末内の履歴から作る）

作り方の注意:
- 入力欄は撮影画面に置く（撮る前に機器名を選び、撮った写真にその機器名が付く）。真値は数値だけ受け付け、空欄はnullにする。
- 機器名の候補は、キューに残っている過去の `deviceName` から重複を除いて作ってよい（新しい順）。新しい保存先（DBのテーブル追加など）を作る必要があれば、作る前に大久保へ相談する。
- **`queue/` 配下と送信先の設定画面（`settings/`）は大久保が作っているので触らない。** `CaptureMeta` に項目が足りなければ、変えずに相談する。
- 撮影のたびに機器名を入れ直さなくて済むよう、直前の機器名を残しておく。

検証:
- `gradlew test` と `assembleDebug` を実行し、件数と結果を記録する（最新mainのAndroidテストは108件のはずです。違えば、その件数を記録して大久保に伝える）。
- 実機で、(a) 機器名と真値を入れて撮影 (b) 両方空で撮影 (c) 候補から選んで撮影、の3通りを行い、履歴画面（SK-06）で機器名が表示されることを目視する。PCの受信口につないでいれば、PCの一覧に機器名が出ることも見る（つないでいなければ「未確認」と書く）。
