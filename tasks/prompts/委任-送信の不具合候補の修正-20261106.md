## 正本(先に全部読む)
`tasks/reports/送信不具合候補の調査-20261106.md`(agy Gemini作の調査報告。*根拠のファイルと行番号つき*。ただし、報告の一部は推測(確度:中)なので、**あなた自身が該当コードを読んで、事実かどうかを確かめてから直す**)。背景: メンバー(SK)の実機確認で、(1)PCの受信口を止めて撮影したら、接続状況の帯は「PCに届かない(送信箱に保存中)・未着2件」(黄)なのに、履歴の行は「未送信」のままで、理由も「今すぐ送る」も出ない。(2)QR登録の直後の、最初の1枚が、2枚目を撮るまで「未送信」のままだった。

## 直すこと
1. **履歴と帯の「未着」の定義と文言を揃える**(不具合1。報告の案3・気づき3): `ui/ConnectionStatus.kt`(帯)と、`ui/QueueDisplay.kt`・`ui/QueueListScreen.kt`(履歴)。PENDING(未送信)の行にも、PCに届かない状況では、状態の説明と、「今すぐ送る」が使えるようにする。具体案: PENDING の行は「未送信」のままでよいが、(a)PCに届かない(帯が黄/赤)ときは、行の下に理由(例: 「PCに届いていません。接続できません」。`lastError` が無いときは、帯の接続状況の理由を使う)を出す、(b)見出し下の要約に、PENDING の件数も含めて「未送信: N件(端末に保存済み)」を出し、「今すぐ送る」ボタンを、PENDING があるときも出す。帯の文言「送信箱に保存中」は、実際に送信箱へ保存された件数があるときだけ使い、すべて PENDING のときは「送信待ち」などに分ける。点検の写真(`isSendable == false`。作業中の点検の写真)は、意図的に送らないので、行に「点検中(完了すると送信します)」と出し、「今すぐ送る」や未着の件数に含めない(報告の気づき2)。別PC宛ての保留(`isHeldFor`)の行の表示は、今のまま(#113)で、壊さない。
2. **送信先未設定の誤った理由**(報告の気づき1): `QueueSendWorker.kt` と `SendRouter.kt`。疎通確認に失敗して `httpSender` が null になると、`fallbackReason` が「送信先未設定」になる。送信先は設定されている。本来の理由(疎通確認の失敗理由。例: 「PC未接続: 接続できません」)が、送信箱へ回った項目の `lastError` と、詳細ダイアログの「直近の失敗の理由」に入るようにする。送信先が本当に未設定のときだけ、「送信先未設定」とする。
3. **登録直後の最初の1枚が送られない**(不具合2。報告の案1・案2・案4): 原因は、報告では「QR登録の完了時に、写真0件で `enqueueSend` を呼ぶ」と「`ExistingWorkPolicy.APPEND_OR_REPLACE` + `Result.retry()` のバックオフでチェーンが待たされる」「`SharedPreferences.apply()` の反映遅れ」の組み合わせという見立て(確度:高〜中)。**あなたが、`PairingScreen.kt`、`MeterCaptureApp.kt`、`QueueSendScheduler.kt`、`QueueSendWorker.kt`、`ReceiverSettings.kt` を読んで、実際にそうなるかを確かめ**、次のうち、安全なものを選んで直す(選んだ理由と、選ばなかったものの理由を、PRの説明に書く):
 - 登録完了時の `enqueueSend` は、未送信が1件以上あるときだけ呼ぶ(案1。小さく安全)。
 - `savePaired` の `apply()` を `commit()` にする(案4。設定は数キーで、ブロックは僅か)。
 - 案2(`REPLACE` への変更)は、*実行中のWorkerを途中でキャンセルし、送信の途中で中断する*リスクがある(`SENDING` のまま残る。`recoverInterruptedSends` がある)。採るなら、そのリスクが無いことを、コードとテストで示す。そうでなければ、`APPEND_OR_REPLACE` を維持し、`doWork` の例外で `Result.retry()` に入ってもチェーンが長く止まらないよう、(例外を握りつぶさずに記録したうえで)再試行の方針を見直す、など、別の安全な方法を提案して実装する。
 - 撮影の保存(`enqueue`)の*後*にだけ送信を起動する順序になっているかを確認する(保存前にWorkerが走って0件で終わる競合がないか)。
4. 上記で見つけた、その他の送信まわりの問題があれば、PRの説明に書く(直すのは上の1〜3の範囲だけ)。
