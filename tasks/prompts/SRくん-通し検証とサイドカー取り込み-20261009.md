## 0. このプロジェクト全体について

工場のアナログメーターの値を、現場のAndroidアプリで撮影し、画像だけをPCへ送って読み取り、一覧で見られるようにするシステムを作っている。目標は11月頃の通しデモ（撮影 → 送信 → PC取り込み → 読み取り → 一覧）。

担当:
- SRくん（あなた）: PC側の取り込み（フォルダ監視、重複排除、パイプライン呼び出し、サイドカーJSON読み取り）
- 大久保: 全体の判断とレビュー
- SKくん: Androidアプリ / YMさん: レコード定義と保存規約 / KPくん: 出力・一覧

PC側の取り込みは、あなたが書いた `watcher.py` と `sidecar.py` の上に乗っている。**今回の作業は、それが実際に動くかを自分の環境で確かめること。** 新しい機能は足さない。

### (B) 取り込みの通し確認（SR-05 / SR-04）

1. 監視を開始する（別のPowerShellウィンドウを開いたままにする）:
   `venv\Scripts\python.exe manager\watch_inbox.py --watch-dir incoming`
2. 次の2つを `incoming` フォルダに置く。画像は `meter2.jpg`（企業提供画像ではないストック画像）を使う。

     ```
     {"device_name": "テスト圧力計", "operator_value": 50.0, "operator_note": "確認用"}
     ```
3. 監視の画面に、取り込みが成功した表示（`stage=ok` など）が出ることを確認し、出力を貼る。
4. Web UIの一覧（`app.py`、SETUP.mdの起動手順どおり）を開き、**1行増えている**ことを目視する。

### (C) 確認すること（1つずつ「確認した / 失敗 / 未確認」を書く）

1. 同じ画像をもう一度 `incoming` に置く → 「重複画像のためスキップしました」と出て、一覧の件数が増えない。（SR-06）
2. `images\` フォルダに、原画像が **SHA-256の名前** で保存されている。（YM-03）
3. サイドカーの `operator_value` を **入れない** JSON（項目を削除したもの）で、別の画像を取り込む → 落ちずに取り込まれる。未入力の値も受け付けることを確認する。（SR-04）
4. 拡張子が大文字（例: `.JPG`）の画像でも取り込まれるか確認する。取り込まれない場合は、その挙動を報告するだけにする（直さない）。

## 2. 守ること

- **想定と違う挙動を見つけたら、直す前に報告する。** 報告には、再現手順・置いたファイル名・監視画面の出力全文を含める。
- テストを落としたとき、期待値やアサーションを緩めて通さない。
- `images\`、`manager.db`、`incoming` の中の画像、出力CSVをコミットしない。`git add -A` を使わず、ファイルを1つずつ指定する。
- コミットとpushは、今回の確認が終わって大久保と相談してから行う。今日はしない。
- `print()` に絵文字を使わない（cp932で `UnicodeEncodeError` になる）。
- 企業提供画像を外部に出さない（ガイドライン: `tasks/企業提供画像の取り扱い.md`）。
