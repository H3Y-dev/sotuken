## 3. 見つかった問題

### 3-1. 実行するとその場で落ちる（AttributeError）

```
res = self.manager.process_image(...)
...
if res.stage == "ok":
```

`manager.process_image()` の戻り値は **辞書**（`{"reading": ..., "val": ..., "stage": ..., ...}`）です。`res.stage` のようなオブジェクト属性アクセスはできません。正しくは `res["stage"]` です。

**本人（大久保）が実際にテストを実行したところ、この行で `AttributeError: 'dict' object has no attribute 'stage'` が出て、テストがそのまま落ちました。** （今朝の `main.py` でも同じ種類の間違いがあり、そちらは本人が直しています。`manager.process_image()` の戻り値の形は、今の `manager/manager.py` の中身を実際に読んで確認してください）

### 3-2. テストの読み込み自体が失敗する

`manager/test_batch.py` の

```python
from manager.manager import MeterManager
```

という書き方は、`venv\Scripts\python.exe -m unittest discover -s manager -p "test_*.py"` で実行すると **`ModuleNotFoundError: 'manager' is not a package` になります。**

`manager/manager.py` の冒頭のコメントに、この理由が書いてあります。

> テスト側: sys.path に manager/ を追加して `from manager import MeterManager`
> （manager.py 自体がトップレベルのモジュールとして読み込まれる）
> `from manager.storage import ...` と書くと前者で「'manager' is not a package」になり、テストが壊れる。

`test_manager.py` や `test_integration.py` は `from manager import MeterManager` と書いています。**`test_batch.py` も同じ書き方に直してください。**

### 3-3. 重複判定がファイル名（パス）になっている

`get_unprocessed_images()` は、**ファイルの絶対パス文字列**でDBの既存レコードと突き合わせて重複を判定しています。これだと、**同じ写真でもファイル名が変われば「新しい写真」として二重に取り込まれてしまいます**（スマホから2回エクスポートすると別名になる、など）。

**画像の中身のハッシュ（SHA-256）で判定してください。** 詳しいやり方は下記の設計書に書いてあります。
