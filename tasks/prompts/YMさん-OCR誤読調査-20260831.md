## 1. 何が起きているか

`気密試験_昇圧後圧力計.jpg`（企業提供の圧力計、真値0〜150MPa）で、検出された目盛りの
範囲が `0〜108` になっています（本来は `0〜150`）。

**原因: 目盛りに書かれた `100` という数字を、OCRが `108` と読み間違えています。**
`108` は圧力計の目盛りとしては半端な数字（切りの良い数字＝標準数ではない）なので、
本来なら「これはおかしい」と判定して弾きたいところですが、今のロジックでは
弾けずにそのまま採用されてしまっています。

## 2. 見てほしい場所

`scale_value_detect.py` に、OCRの文字を数字に変換する前処理として
`_normalize_ocr_text()` という関数（54行目付近）と `_CONFUSION_MAP`
（似た形の文字を正しい数字に直すための対応表）が既にあります。

```python
def _normalize_ocr_text(text):
    return text.translate(_CONFUSION_MAP)
```

**まず`_CONFUSION_MAP`の中身を確認してください。** `0`と`8`の見間違い
（低解像度や印字のかすれで、`0`が`8`に近い形に見えることがある）に対応する
項目が入っているか調べ、無ければ調査してください。

もう1つの手がかりとして、`is_plausible_fullscale()`（766行目付近）という
「フルスケールとしてありえる値か（標準数かどうか）」を判定する関数もあります。
`108`が目盛りの最大候補になった時点で、この関数を使って「これは怪しい」と
弾けないか（すでに使われているならなぜ今回効かなかったか）も合わせて調べてください。

2. **対策案を考えて実装する。** 例えば、`0`と`8`の混同に対する`_CONFUSION_MAP`の

   **原因を見てからYMさん自身に一番良い方法を考えてもらってください**
3. **他の画像で退行しないことを確認する。** 特に本物の`8`が写っている数字
