# KPくんのSprint 1〜8ロードマップ

担当範囲は、保存されたレコードをCSV・JSONLへ出し、一覧とグラフで見られるようにする部分です。<br>
将来の外部サーバー接続と出力を分けるアダプタも担当します。

1スプリント = 学校での作業日1回 = 3時間です。デモ予定は2026年10月末から11月初です。読み取り精度は2026-09-01に凍結済みで、この表には精度を改善するタスクは含まれません。

## 全体の流れ

```text
【SKくん】撮影(Android) → 未送信キュー(Android) [本人（大久保）]
        → 公開フォルダまたはHTTPで送出 [本人（大久保）]
        → 【SRくん】PC側の監視フォルダ → 取り込み → 既存パイプラインで読み取り
        → 【YMさん】レコード保存（原画像・ログの保管を含む）
        → 【KPくん: CSV/JSONL出力・一覧・グラフ・アダプタ】
```

### 検証のしかた

- S1-ALL: 合意メモを全員で読み合わせる。SKくんは雛形をビルドして実機起動を目視し、PC側は共通テストコマンドを実行する。
- KP-02: 対象関数の単体テストと共通テストコマンドを実行し、入力例と戻り値を目視する。
- KP-03: 出力ファイルをExcelで開き、文字化け・列ずれがないことを目視する。共通テストコマンドを実行する。
- KP-04: 2件以上を出力して行数を数え、各行をJSONとして読み戻す。共通テストコマンドを実行する。
- KP-05: 用意した複数レコードを画面で絞り込み、表示内容をCSV・JSONLと目視照合する。
- KP-06: 複数機器・複数日の入力を画面で切り替え、表示点と一覧を目視照合する。
- KP-07: 定義書をCSV/JSONL出力の入力と照合し、本人が「実接続コードなし」をレビューする。
- KP-08: 手書きのダミーレコードから変換し、`evaluate.py`へ渡して読み込みが通ることを確認する。真値欠損・フルスケール欠損の各ケースで除外件数を確認する。

## 待たなくてよいもの

KP-02はYM-02の完成を待ちません。参照するのは仕様書のスキーマ表であって、YMさんの実装物ではないためです。手書きのダミーレコードで先に進めます。

仕様書への依存と、他人の実装物への依存は別です。仕様書で確定した項目を参照するだけなら実装完成を待たず、実際に他の人のコードを呼ぶときだけ待ちます。
