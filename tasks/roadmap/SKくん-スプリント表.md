# SKくんのSprint 1〜8ロードマップ

担当範囲は、`android/app/src/main/kotlin/jp/sotuken/metercapture/ui/` 配下のAndroid画面です。<br>
撮影、ガイド表示、キュー画面、任意入力フォームを担当します。Androidは実機での目視確認が中心です。

1スプリント = 学校での作業日1回 = 3時間です。デモ予定は2026年10月末から11月初です。読み取り精度は2026-09-01に凍結済みで、この表には精度を改善するタスクは含まれません。

## 全体の流れ

```text
【SKくん: 撮影・画面】撮影(Android)
        → 未送信キュー(Android) [本人（大久保）]
        → 公開フォルダまたはHTTPで送出 [本人（大久保）]
        → 【SRくん】PC側の監視フォルダ → 取り込み → 既存パイプラインで読み取り
        → 【YMさん】レコード保存（原画像・ログの保管を含む）
        → 【KPくん】CSV/JSONL出力・一覧・グラフ・アダプタ
```

- S1-ALL: 合意メモを全員で読み合わせる。雛形をビルドしてSKくんの実機で起動を目視し、PC側は共通テストコマンドを実行する。

- SK-03: 実機で撮影し、端末上の保存先と画像を目視する。
- SK-04: 実機プレビューで枠を目視し、枠内外で撮影できることを確認する。
- SK-05: 実機をオフラインにして複数枚を撮影し、キュー一覧の件数を目視する。
- SK-06: 状態の異なる3件を用意し、実機画面で4項目と状態を目視する。
- SK-07: 入力あり・未入力の各ケースを実機で撮影し、キューのメタデータを目視する。

## 待たなくてよいもの

SKくんの担当タスクには、計画書で個別に「〜を待たない」と書かれた注記はありません。表の依存だけを守り、同じSprint内の他担当の実装待ちは作らないでください。

仕様書への依存と、他人の実装物への依存は別です。仕様書で確定した項目を参照するだけなら実装完成を待たず、実際に他の人のコードを呼ぶときだけ待ちます。

## 遅れたときに削るもの

4番目の削減候補はSK-04の撮影ガイド枠です。通しで1本通ること（Sprint 5）と、版間比較（Sprint 8）は削りません。
