# 作業をGitHubに共有する手順（開発未経験でも分かる版）

作業が完了したら、この手順で共有してください。**このファイルの内容をまるごと
自分が使っているAI（Claude/Gemini）に貼り付けて、「この手順通りに一緒にやってほしい」
と頼めば大丈夫です。** 分からない用語・分からない画面が出てきても、慌てず質問してください。

---

## そもそも何をするのか（先に全体像）

自分のPCの中で作った変更（コードの修正）は、**そのままでは自分のPCの中にしか
存在していません。** これをチーム全員が使う「本番のコード置き場（GitHub）」に
送って、ようやくチームの成果になります。

今回やることは3ステップだけです。

1. **最新の状態を自分のPCに取り込む**（他のメンバーが先に進めた分を反映する）
2. **自分の変更をGitHubに送る**（push＝プッシュ）
3. **「これ取り込んでください」とお願いする**（Pull Request＝プルリクエスト、略してPR）

以降、それぞれ詳しく説明します。

---

## 使う言葉の意味（先に読んでおくと迷わない）

| 言葉 | 意味 |
|---|---|
| **コミット (commit)** | 変更の「セーブポイント」。作業の区切りごとに保存しておく記録 |
| **ブランチ (branch)** | 自分専用の作業スペース。他の人の作業を邪魔せずに、自分の変更だけを進められる場所 |
| **main（メイン）** | 全員の完成した作業が集まる「本流」。ここが実際に動くプログラムの本体になる |
| **push（プッシュ）** | 自分のPCの変更を、クラウド上のGitHubへ送ること |
| **fetch（フェッチ）** | GitHub側の最新情報を、自分のPCに取り込むこと（ファイルの中身はまだ変わらない、情報だけ先に取ってくるイメージ） |
| **rebase（リベース）** | 自分の作業を、最新のmainの続きに"乗せ直す"こと。詳しくは下で説明 |
| **Pull Request（PR、プルリクエスト）** | 「このブランチの内容をmainに取り込んでいいですか？」というお願い。GitHubの画面上でボタンを押して作る |
| **conflict（コンフリクト、競合）** | 同じ場所を複数人が別々に変更していて、どちらを採用するかコンピュータが自動で決められない状態。エラーではなく「人間に確認してほしい」というサイン |

---

## なぜ順番が大事なのか（たとえ話）

みんなで1冊のノートを共同で書いていると想像してください。

- あなたがノートを開いた後、**他の人がノートの内容を書き足していた**とします
- それに気づかず、自分の手元にある「古いコピー」に書き足して、それをそのまま
  上書き保存してしまうと、**他の人が書いた分が消えてしまいます**

これを防ぐのが「最初に最新の状態を取り込む」という手順です。実際に今日、
古い状態のまま作業していたブランチがあり、**もしそのままmainに取り込んでいたら
直近数日分の作業が消えるところでした。** だから最初のステップが一番大事です。

---

## 手順

### ステップ1: 最新のmainを自分の作業に取り込む

ターミナル（黒い画面、コマンドを打つところ）で、自分の作業フォルダに移動してから
次の2行を実行します。

```bash
git fetch origin
git rebase origin/main
```

**これは何をしているか**: 1行目でGitHub側の最新情報を確認し、2行目で
「自分の変更を、その最新の状態の上に乗せ直す」ということをしています。

**もし「conflict」というエラーが出たら**: 焦らなくて大丈夫です。これは
「同じ場所を2人が触っていて、どちらを残すか人間に決めてほしい」というだけの
状態です。自分で判断しようとせず、AIに次のように聞いてください。

> 「rebaseでconflictが出ました。どうすればいいですか？」

AIが該当ファイルの中身を一緒に見ながら、どちらを残すか一緒に決めてくれます。

### ステップ2: 自分の変更をGitHubへ送る（push）

まず、自分の作業に名前（ブランチ名）を付けます。何をやったか分かる名前にしてください。

```bash
git push -u origin <ブランチ名>
```

ブランチ名の例（`<ブランチ名>`のところに入れる）:
- SKくん: `feature/t1-2-circle-fit`
- SRくん・KPくん: `feature/t6-manager`
- YMさん: `feature/t3-orientation`

**初めてpushするとき**、GitHubへのログイン確認（ユーザー名やパスワード、
または「ブラウザで認証してください」という表示）が出ることがあります。
出てきた指示に従えばよいですが、分からなければそのままAIに画面の内容を
伝えるか、本人（大久保）に連絡してください。

### ステップ3: 「取り込んでください」とお願いする（Pull Request）

pushが終わると、画面に次のような案内が出ます。

```
remote: Create a pull request for '<ブランチ名>' on GitHub by visiting:
remote:      https://github.com/H3Y-dev/sotuken/pull/new/<ブランチ名>
```

この`https://`から始まるリンクをコピーして、**ブラウザ（Chrome等）に貼り付けて
開いてください。**

もしこの案内が見当たらない場合は、代わりに次の手順でも同じことができます。

1. ブラウザで `https://github.com/H3Y-dev/sotuken` を開く
2. 画面上部あたりに「Compare & pull request」という緑または黄色のボタンが
   出ているので、それをクリック
3. タイトルの欄に、何をやったか一言書く（例:「T1-2 円フィッティングと選択ロジック」）
4. 説明欄には、日報に書いた内容をそのままコピペしてOK
5. 一番下の緑のボタン「Create pull request」をクリック

**これで完了です。** 以降のチェック・取り込みは本人（大久保）が行います。
自分でこれ以上操作する必要はありません。

---

## 完了したら

- PRを作ったら、**Slackで「PR作りました」と一言連絡**してください（リンクを貼るとより親切です）
- 取り込まれる（マージされる）まで、同じ作業を続けて構いません。追加でコミットして
  もう一度pushすれば、自動的にPRの内容が更新されます
- 「ここを直してほしい」という指摘が来ることがあります。その場合は指摘通りに直して、
  もう一度pushすれば大丈夫です（PRを作り直す必要はありません）

---

## 困ったとき・不安なとき

- **何が起きているか分からなくなったら、まず`git status`を実行**して、
  その結果をそのままAIに見せてください。今どういう状態か教えてくれます
- **意味の分からないエラーが出ても、焦って何かを削除・上書きしようとしないでください**
- 特に次の2つのコマンドは、**AIか本人（大久保）に確認してから**でないと実行しないでください
  （データが消える可能性があるコマンドです）:
  - `git reset --hard`
  - `git push --force`
- 「分からない」と言うことは全く問題ありません。AIに「今何をしているところで、
  次に何をすればいいか分からない」と正直に伝えれば、状況を確認しながら
  一緒に進めてくれます

## チーム共通の落とし穴：`print()`に絵文字を使うと実行時にクラッシュする

2026-08-24、2人のメンバーの提出物で**同じ原因のエラーが立て続けに発生**しました。
自分のコードにも当てはまっていないか、pushする前に確認してください。

**症状**: 自分のPC（Windows）で実行すると、途中で次のようなエラーが出て止まる。

```
UnicodeEncodeError: 'cp932' codec can't encode character '\U0001f680' in position 0: illegal multibyte sequence
```

**原因**: `print()`の中に絵文字（🚀 ✅ ❌ ⚠️ 📄 🔢 🖼️ など）を使っていると、
Windowsの標準の文字コード（cp932）ではその文字を画面に出せず、プログラムが
止まってしまいます。日本語の文章自体は問題ありません。**絵文字だけが原因です。**

**直し方**: `print()`の中の絵文字を、`[OK]` `[NG]` `[結果]` `[警告]`のような
普通の文字・記号に置き換えるだけで直ります。

```python
# 直す前（クラッシュする）
print("🚀 処理を開始します")
print(f"❌ 画像読み込み失敗: {filename}")

# 直した後（問題なく動く）
print("[開始] 処理を開始します")
print(f"[NG] 画像読み込み失敗: {filename}")
```

自分のコードに絵文字を使った`print()`が無いか、一度確認してみてください。
分からなければAIに「このファイルにcp932でクラッシュする絵文字printが無いか
確認して」と頼めば探してくれます。
