# 送信不具合候補の修正完了報告（2026-11-09）

## 1. 概要

## 2. 修正内容

### 課題1: 未着・未送信件数の定義と表記の統一
- **`ConnectionStatus.kt`**:
  - `countUndelivered` に `isSendable: Boolean = true` フィルタを追加し、未完了点検中の写真（送信不可）を未送信件数から除外。
  - `connectionBarText` に `hasOutbox: Boolean = true` 引数を追加。送信箱に送信対象がある場合は「（送信箱に保存中）」、送信箱が空でPENDING項目のみの場合は「（送信待ち）」と表示を区別。
- **`NetworkStatus.kt`**:
  - `connectionBarTextWithNetwork` に `hasOutbox` パラメータを伝搬。
- **`QueueDisplay.kt`**:
  - `sendStatusLabel`: 送信不可（`!isSendable`）の写真について「点検中(完了すると送信します)」と表示。
  - `undeliveredSummary`: 送信可能なPENDING項目を「未送信: N件（端末に保存済み）」としてカウント・表示。点検中や保留中の写真は除外。
  - `errorTextFor`: PC未接続・未到達（`connectionUnreachable == true`）かつPENDINGの項目に対し、「PCに届いていません。$reason」と表示。
  - `canRetry`: `isSendable` が false の項目はリトライ不可とする。
- **`QueueListScreen.kt`**:
  - `QueueListScreen`, `QueueListRow`, `FullImageDialog` に `connectionUnreachable`、`connectionReason`、`isSendable` を伝搬。
  - PENDING項目に対しても未到達理由を表示し、PENDING項目が存在する場合も「今すぐ送る」ボタンを活性化。
- **`MeterCaptureApp.kt` & `InspectionScaffold.kt` & `InspectionApp.kt`**:
  - `hasOutbox` の真偽値を正しく算出し、バーおよびキュー画面へ渡すよう配線。

### 課題2: PC停止時に「送信先未設定」と誤表示される問題の修正
- **原因**:
  - `QueueSendWorker.kt` において、ヘルスチェック失敗時に `reach.url` が null となり、`val sender = reach.url?.let { HttpSender(...) }` が null になっていた。
  - そのため `SendRouter.send()` 呼び出し時に `httpSender` が null となり、ルーター側が「送信先未設定」と判定して `lastError` に記録していた。
- **修正**:
  - 設定自体が存在する（`settings.isConfigured()` が真）場合は、ヘルスチェック到達成否に関わらず設定済みURLからfallback用HttpSenderを構築して `SendRouter` に渡す。
  - これにより `SendRouter.send()` 内の `healthChecker()` が実行され、`reach.error`（例: `PC未接続: failed to connect to ...`）が正しく `lastError` に記録・反映されるように修正。

### 課題3: ペアリング直後の初回写真送信不具合の修正とWorkerリトライ制御
- **修正**:
  - **`PairingPayload.kt` & `PairingScreen.kt`**:
    - `shouldEnqueueSendOnPairing(pendingCount)` 関数を追加し、ペアリング完了時に未送信件数が0件の場合は即時enqueueSendを呼ばないように制御（不要なWorker起動による競合を防止）。
  - **`QueueSendWorker.kt`**:
    - 予期せぬ例外発生時の戻り値を `Result.retry()` から `Result.failure()` に変更。WorkManagerの `APPEND_OR_REPLACE` 戦略下で失敗タスクが指数バックオフ状態のままキューに居座り、後続の送信トリガーがブロックされる問題を解消。
  - **設計判断（案4の不採用について）**:
    - `ReceiverSettings.kt` の `apply()` を `commit()` に変更する案（案4）は、既存の単体テスト（`PairedSettingsTest`）が `SharedPreferences.Editor` の `apply` 呼び出し回数を検証しているため互換性が崩れること、またAndroidの `apply()` は呼び出し元スレッドのインメモリキャッシュを即時同期更新するため同一プロセス内での不整合は発生しないことから不採用とし、案1（0件時enqueueスキップ）+ Workerリトライ適正化によって安全に問題を解決。
