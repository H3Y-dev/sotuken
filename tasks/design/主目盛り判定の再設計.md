# 主目盛り（is_major）判定の再設計

作成: 2026-08-26 ／ 担当: 本人

目盛り位置の検出（角度方向の周期性ベース、`70e078d`）は完了した。
**次のボトルネックは主目盛りの判定。** ここが壊れているため、OCRの数字を
目盛りに対応付ける段階で失敗し、ゼロ点・フルスケール点が誤った位置に付く。

---

## 現状の問題（実測）

`気密試験_昇圧後圧力計.jpg`（0〜150MPa、主目盛りは0/50/100/150の4本）で、
検出された23本を角度順に並べ、主目盛り判定を記号化すると次のようになる。

```
MMM.M.................M
```

**主目盛りが3つ連続している**（156.2° / 165.1° / 173.9°、間隔8.9°）。
実際の主目盛りは約88°間隔なので、これはあり得ない。

### 原因: 撮影の遠近で目盛りの長さが場所により2倍近く違う

| 領域 | 検出された長さ |
|---|---|
| 156〜191°（左上） | 41〜55 |
| 218〜315°（右） | **23〜31** |
| 351°（下） | 48 |

同じ副目盛りでも、盤面が斜めを向いているため**手前側が長く写る**。

現在の `is_major` は `長さ > 全体の中央値 * 1.3` という**単一のしきい値**なので、
**遠近差だけで左上の副目盛りが全部「主目盛り」と誤判定される。**

---

## 再設計の方針

次の3つを組み合わせる。単独では不十分。

### 1. 主目盛りは連続しない

**隣接する目盛りを同時に主目盛りとしない。** 主目盛りの間には必ず副目盛りが
複数（通常4〜9本）入る。

上記の `MMM.M...` のような並びは、この制約だけで棄却できる。

### 2. 主目盛りは等間隔に現れる

主目盛りは副目盛りn本ごとに1本、という規則的な間隔を持つ。
**目盛り位置の検出で既に周期構造を求めているので、その情報を使う。**

長さで個別に判定するのではなく、
「n本ごとに1本」という**周期モデルを当てはめ、最も当てはまりの良い n と位相を選ぶ**。
こうすれば、多少長さがばらついても正しい位置に主目盛りが立つ。

### 3. 長さの比較を局所的に行う

全体の中央値と比べるのをやめ、**近傍の目盛りの長さと比べる。**
遠近による全体的な傾きを打ち消せる。

例: 各目盛りについて、前後k本の長さの中央値を基準にして相対比を取る。

## 検証方法

**数値だけで判定しない。必ず画像を見る。**

```
venv\Scripts\python.exe tools_render_overlays.py --no-vlm
```

`eval/overlays/` の9枚を開き、**マゼンタ（主目盛り）が実際の主目盛り
（数字が振られている長い線）の上に乗っているか**を確認する。

### 期待する状態

| 画像 | 主目盛りがあるべき位置 |
|---|---|
| 気密試験_昇圧前/後 | 0 / 50 / 100 / 150 の4本 |
| 耐圧試験_昇圧前/後 | 0 / 100 / 200 / 300 / 400 の5本 |
| 134647 / 134656 / 134745 | 0 / 20 / 40 / 60 / 80 / 100 の6本 |
| meter1 | 0 / 10 / ... / 150 |
| meter2 | 0 / 10 / ... / 100 |

**主目盛りが連続していないこと**を、画像と記号列（`MMM.M...`形式）の両方で確認する。

### 数値での確認

```
venv\Scripts\python.exe evaluate.py eval/groundtruth.json --no-vlm -o eval/rep_major2.json
```

現在（2026-08-26）の値:

```
読取成功   9/9
許容誤差内 6/9
平均       4.72 %FS
中央値     1.47 %FS
```

**特に「検出範囲が真値と一致するか」を見る。** 現在9枚中4枚が範囲NG。
主目盛りが正しくなれば、ゼロ点・フル点の誤配置が減り、ここが改善するはず。

## 関連する未解決の問題（この設計とは別）

目視検証で、失敗の原因は3つに分かれることが分かっている。
**本設計が解くのは1番のみ。**

1. **主目盛りの判定破綻**（耐圧試験_昇圧後など） ← 本設計の対象
2. **端の目盛りが欠ける**（気密試験_昇圧後: 150付近に検出点が無い）
   - 櫛モデルの当てはめ範囲が足りていない可能性。1と同じ根かもしれない
3. **針が0の目盛りを隠す**（耐圧試験_昇圧前: 0の位置に検出点が無い）
   - 検出できないものには点を打てない。遮蔽対策が別途必要。
   - VLMへの問い合わせ（`check_needle_overlaps_zero`）は実装済みだが、
     4Bモデルでは4枚すべて同じ答えを返して機能しなかった（2026-08-25検証）
4. **OCRの誤読**（134647: 0→2、100→111）
   - 90度回転した画像で発生。T3（向き正規化）の領域
