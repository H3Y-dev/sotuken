# 実機確認チェックリスト（スマホ ⇄ PC の通し）

スマホ（Android）とPCをつないで、撮影から点検結果までを実機で確かめるための手順です。上から順に進めてください。

この表の文言・コマンド・挙動は、2026-11-06 時点の main（52c9dd6）のソースを読んで確かめたものです。ソースだけでは確かめられなかった点は「**未確認**」と書いています。

## 0. 前提と所要時間

所要時間の見込みは **約75分** です（実機での測定はしていません）。内訳は、準備10分、1〜4章で40分、5章で15分、6〜8章で10分です。5章の自動送信を待つと、さらに最大15分かかります。待たずに「今すぐ送る」だけで進めるなら、約60分です。

- [ ] PCのIPv4アドレスを控えた: `ipconfig` の「IPv4 アドレス」の値（例: `192.168.1.20`）。これを以降 `<PCのIP>` と書く
- [ ] スマホとPCが**同じWi-Fi**につながっている（モバイル回線はオフ。ゲストWi-Fiなど端末同士が見えない設定でないこと。後者は**未確認**）
- [ ] スマホのアプリを入れてある: パッケージ名 `jp.sotuken.metercapture`、versionName `0.1.0`（versionCode 1）。ソースの値なので、入れたAPKが今のmainからのビルドかを確かめる（確かめ方は**未確認**。ビルドした日時を結果記録欄に書いておく）
- [ ] PCのリポジトリが main の最新で、`incoming/` と `manager.db` の中身を把握している（8章で片付けるときに必要）
- [ ] スマホの時刻が正しい（QRの期限の判定に端末時刻が使われる）
- [ ] 測る対象は、**機器のQRラベルが写るメーター**を1つ以上用意した（7章で必要。理由は7章）

> [!NOTE]
> 送信先は「PCの受信口」（`manager/receiver.py`）です。スマホは `http://<PCのIP>:8765` へ HTTP で画像を送ります。認証はヘッダー `X-Sotuken-Token`（合言葉）です。

## 1. PC側の起動

### 準備
- [ ] ポート 8765 を他のプログラムが使っていない
- [ ] リポジトリ直下で作業する（`manager/pc_config.json` が無ければ初回起動で自動作成される。合言葉と受信口のIDが入る）

### 手順
- [ ] PowerShell をリポジトリ直下で開き、次を実行する
  ```powershell
  python run_pc.py
  ```
- [ ] コンソールに `[受信口] 待ち受け開始: http://<PCのIP>:8765` と出る
- [ ] ブラウザでアプリ（`app.py`、Streamlit）が開く。開かなければコンソールに出るURLを開く（Streamlit の既定は `http://localhost:8501`。リポジトリ内では指定していないので**未確認**）
- [ ] 画面の左サイドバーに見出し「**スマホの送信先**」、「**送信先URL**」（`http://<PCのIP>:8765`）、折りたたみ「**手入力用の合言葉を表示**」、ボタン「**スマホを登録**」「**登録を中止**」がある

### 期待される結果
- [ ] 送信先URLのIPが、手順0で控えた `<PCのIP>` と同じ
- [ ] 画面上部のタブは「読み取り」「記録」「点検結果」の3つ

### 違ったときに見る場所
| 症状 | 見る場所 |
|---|---|
| サイドバーに「受信口が起動していません: ポート 8765 が使用中または起動できませんでした（…）」 | 別の `run_pc.py` や `python -m manager.receiver` が動いていないか。動いていれば止める |
| 「別プロセスで起動済みです」の表示 | 受信口が別プロセスで動いている。この画面では QR登録ができない（「QR登録は受信口を起動した画面で行ってください。…」と出る）。別プロセスを止めて画面を再読み込みする |
| コンソールに「受信設定が破損しています。原本を保持し退避しました: …」 | `manager/pc_config.json` が壊れている。退避ファイル `pc_config.json.corrupt-*` を確かめる。**削除すると合言葉が変わり、スマホの再登録が必要になる** |
| 送信先URLのIPが違う（VPN・仮想NICなど） | `ipconfig` で本来のWi-FiのIPを確認する。自動で選ばれるIPの決め方は**未確認** |

## 2. QR登録（ペアリング）

QRの有効期間は **5分**（300秒）で、**1回使うと無効**になります。

### 準備
- [ ] 1章が済み、サイドバーが表示されている
- [ ] スマホのカメラ権限を許可できる（アプリの「カメラを許可」ボタン）

### 手順（成功パターン）
- [ ] PCのサイドバーで「**スマホを登録**」を押す
- [ ] QRが出て、キャプション「スマホの送信先QR読取で登録してください」「残り N 秒」と、URL（`http://<PCのIP>:8765`）が出る。「残り」は約300から1秒ごとに減る
- [ ] スマホのアプリのトップ画面（見出し「メーター撮影」）で「**送信先の設定**」→「**QRで登録**」を押す
- [ ] 画面「**送信先QRを読む**」（説明: 「PCの「スマホを登録」で表示したQRを撮影してください。」）で、PCのQRを写して撮影する
- [ ] 確認画面に「PC: <PC名>」「URL: http://<PCのIP>:8765」が出る
- [ ] 「**確認して登録**」を押す
- [ ] 画面が閉じてトップに戻る
- [ ] もう一度「送信先の設定」を開くと、送信先URLと合言葉が入っている
- [ ] PCのQRが消えている（サイドバーに「登録済み・期限切れ・中止後は、QRを作り直してください。」）

### 失敗パターン（それぞれ試す）
- [ ] **期限切れ**: QRを出して5分待つと、PCのQRが消える。その後の古いQR（撮影済みの画像など）を登録しようとすると、スマホに「QRが無効・期限切れ・使用済みです。PCでQRを表示し直してください」
- [ ] **使用済み（1回限り）**: 登録に成功したQRで、もう一度登録を試すと、同じ文言になる（PCは403を返す）
- [ ] **読み直し**: 確認画面で「**読み直す**」を押すと、読み取り前に戻る。QRを写し直せる
- [ ] **QR以外を写した**: 「送信先登録用のQRを読み取ってください」、読み取れなければ「QRを読み取れませんでした。撮影し直してください」
- [ ] **QRが2つ写っている**: 「登録用QRを1つだけ写して撮影してください」
- [ ] **スマホの時刻がずれている**: 確認画面に「端末時刻では期限切れです。PCでQRを更新してください。時刻がずれている場合は確認して登録できます。最終判定はPCが行います。」と出る。それでも登録を押せる
- [ ] **PCのURLが変わった**: QRを出した後にPCのIPが変わると、PC側に「PCのURLが変わりました。QRを作り直してください。」と出てQRが消える（再現しにくい。試せなければ**未確認**のままにする）
- [ ] **PCに届かない**: スマホがPCに通信できないと、「PCと通信できませんでした。接続を確認し、PCでQRを表示し直してください」

### 別PCへの変更時の確認（PCが2台あるときだけ。1台なら**未確認**として飛ばす）
- [ ] スマホに「PC未到着」の写真が残っている状態で、**別のPC**のQRを読む
- [ ] 確認画面に「PC未到着の写真がN件あります。既存の写真も新しいPCへ送ります。」が出て、ボタンの文言が「**確認して登録し、新しいPCへ送る**」になる
- [ ] 同じPCを登録し直す場合、または未送信の写真が0件のときは、この警告は出ず、ボタンは「確認して登録」のまま

### 違ったときに見る場所
| 症状 | 見る場所 |
|---|---|
| 「QRが無効・期限切れ・使用済みです」が出続ける | PCでQRを出し直す。それでも出るなら、PCコンソールに `[受信口]` のログが出ているか確認する |
| 「QRとPCの応答が一致しません」 | PCでQRを出し直す。古いQRを読んでいないか確認する |
| 手入力で登録したい | 「送信先の設定」で「送信先URL」と「合言葉 (Token)」を入れて「保存」。合言葉は PCサイドバーの「手入力用の合言葉を表示」。手入力で保存すると、PCのIDと名前の記録は消える |
| 「送信先にはHTTPの私用IPv4とポートを指定してください」 | URLが `http://192.168.x.x:8765` の形かを確認する。ホスト名やHTTPSは使えない |

## 3. LAN接続

### 準備
- [ ] 1章でPCが起動し、2章の登録が済んでいる（未登録でも、この章の疎通確認はできる）

### 手順
- [ ] **PC側で受信口が待ち受けているか**: 次を実行し、`TcpTestSucceeded : True` を確かめる
  ```powershell
  Test-NetConnection 127.0.0.1 -Port 8765
  ```
- [ ] **ファイアウォール**: 初回起動時に Windows の許可確認が出たら、**プライベート ネットワーク**を許可する。出なかった、または許可しなかったなら、スマホから届くか（次の項目）を先に確かめる
- [ ] **スマホのブラウザからPCに届くか**: スマホのブラウザで `http://<PCのIP>:8765/health` を開く
- [ ] 画面に `{"error": "合言葉（X-Sotuken-Token）が一致しないか未指定です"}`（HTTP 401）が出る。**これが「届いている」印**です（ブラウザは合言葉のヘッダーを付けられないため、401で正しい）
- [ ] **アプリ側の確認**: 写真を1枚撮り、履歴（4章）で「PC受信済み」になれば、疎通できている。アプリには単独の「接続確認」ボタンはない（ソース上、見つからなかった）

### 期待される結果
- [ ] スマホのブラウザに上記の401が返る（つながらない・タイムアウトなら NG）

### 違ったときに見る場所
| 症状 | 見る場所 |
|---|---|
| スマホのブラウザがタイムアウトする | (1) 同じWi-Fiか。(2) PCのネットワークの種類が「パブリック」ではないか。(3) ファイアウォールの受信ポート 8765 |
| ファイアウォールで開ける必要がある | 管理者のPowerShellで次を実行する（一般的な方法。**このリポジトリには手順がなく、実機では未確認**）。確認後は 8章で削除する<br>`New-NetFirewallRule -DisplayName "sotuken-receiver-8765" -Direction Inbound -Protocol TCP -LocalPort 8765 -Action Allow -Profile Private` |
| 403「接続元IP（…）が許可されていません（プライベートIPv4または127.0.0.1のみ）」 | スマホのIPがプライベートIP（192.168.x.x など）か。モバイル回線やVPNを経由していないか |
| 401 は出るが、アプリからは届かない | アプリの「送信先の設定」の合言葉が、PCの「手入力用の合言葉を表示」と同じか。2章でQR登録し直す |

## 5. (c) 追い送り（PCを止めて撮る → PCを起動 → 届く）

PCに届かなかった写真は、スマホの送信箱（`Android/data/jp.sotuken.metercapture/files/outbox`。端末側の保存先）に残り、PCが戻ると自動で再送されます。自動の周期は15分です。

### 準備
- [ ] 4章が成功している
- [ ] 履歴が「PC受信済み」の写真だけの状態を控えておく

- [ ] PCの `incoming/` は増えていない
- [ ] PCで `python run_pc.py` を起動し直す
- [ ] **A. 自動で届くか**: スマホを同じWi-Fiにつないだまま、アプリを開いたままで最大15分待つ。「PC未到着」が減って「PC受信済み」になる

- [ ] PCの `incoming/` に3組（画像+JSON）が増える

## 6. (d) 二重登録なし

> [!IMPORTANT]
> PCの動きはソース（`manager/receiver.py`）と、PC上での実測で次のとおりでした。依頼文の「PC側が409を返すこと」は、**同じ内容の再送では当てはまりません**。
> - 同じファイル名・**同じ内容**: HTTP **200**。本文に `"duplicate": true`。保存はしない
> - 同じファイル名・**違う内容**: HTTP **409**（`同名の画像が異なる内容で既に保存されています`）。上書きしない

### 準備
- [ ] 本物の `incoming/` を汚さないよう、**テスト用の受信口**を別ポートで起動する（別のPowerShellで）
  ```powershell
  $t = "$env:TEMP\rx-check"
  python -m manager.receiver --port 18765 --incoming "$t\incoming" --config "$t\cfg.json"
  ```
- [ ] 起動後、`$t\cfg.json` に合言葉（`token`）が作られる。それを控える
- [ ] 適当なJPEGを1枚用意する（例: `C:\temp\sample.jpg`）
- [ ] 次のスクリプトを `dup_test.ps1` として保存する
  ```powershell
  param([string]$Url="http://127.0.0.1:18765",[string]$Token,[string]$Image)
  $bytes=[IO.File]::ReadAllBytes($Image)
  $sha=([BitConverter]::ToString([Security.Cryptography.SHA256]::Create().ComputeHash($bytes))-replace '-','').ToLower()
  $id="chk-"+[guid]::NewGuid().ToString().Substring(0,8)
  $name="20261106T010203_$id.jpg"
  $json='{"local_id":"'+$id+'","captured_at":"2026-11-06T01:02:03Z","device_name":"CHECKLIST-TEST","operator_value":null,"operator_note":"checklist"}'
  $b64=[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($json)).TrimEnd('=').Replace('+','-').Replace('/','_')
  function Send($file,$hash){ curl.exe -s -w "`nHTTP %{http_code}`n" -X POST "$Url/upload" -H "X-Sotuken-Token: $Token" -H "X-File-Name: $name" -H "X-Sidecar-Json: $b64" -H "X-Image-Sha256: $hash" -H "Content-Type: application/octet-stream" --data-binary "@$file" }
  "--- 1回目"; Send $Image $sha
  "--- 2回目（同じ内容）"; Send $Image $sha
  $alt=[IO.Path]::GetTempFileName(); [IO.File]::WriteAllBytes($alt,($bytes+[byte[]](0)))
  $sha2=([BitConverter]::ToString([Security.Cryptography.SHA256]::Create().ComputeHash([IO.File]::ReadAllBytes($alt)))-replace '-','').ToLower()
  "--- 3回目（同名で中身が違う）"; Send $alt $sha2
  Remove-Item $alt
  ```

### 手順
- [ ] 次を実行する
  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File .\dup_test.ps1 -Token <控えた合言葉> -Image C:\temp\sample.jpg
  ```
- [ ] 1回目: `{"stored": "<ファイル名>"}` と `HTTP 200`
- [ ] 2回目: `{"stored": "<ファイル名>", "duplicate": true}` と `HTTP 200`
- [ ] 3回目: `{"error": "同名の画像が異なる内容で既に保存されています"}` と `HTTP 409`
- [ ] `$t\incoming` を開き、画像1つ・JSON1つだけがある（3回送ったのに2ファイル）

> このスクリプトは、2026-11-06 に手元のPCで実行し、上の3つの結果（200 / 200+`duplicate` / 409）になることを確かめています。

### 実機（スマホ）側の確認
- [ ] 5章の追い送りの後、`incoming/` が **写真の枚数と同じ組数**（重複なし）
- [ ] 「今すぐ送る」を続けて2回押しても、`incoming/` の組数が増えない
- [ ] 7章の「記録」タブで、同じ写真が2件並んでいない（PCの取り込み側は画像の SHA-256 が処理済みなら飛ばす。コンソールに「重複画像のためスキップしました」「処理済みのため推論を飛ばした」と出る）

## 7. 点検結果タブ

### 準備
- [ ] PCで、`incoming/` を監視してDBに取り込む**別プロセス**を動かす（**`run_pc.py` は取り込みを起動しない**）
  ```powershell
  python manager/watch_inbox.py
  ```
  - 取り込み先は `manager.db`、原画像は `images/`、オーバーレイ画像は `overlays/`。起動時に既存の画像を取り込む
  - メーター読み取りの処理を行うため、起動と処理に時間がかかることがある（所要時間は**未確認**）
- [ ] 取り込みが終わるとコンソールに `[DB保存] id=…` が出る

> [!WARNING]
> スマホアプリが送るJSONには、**機器ID（`device_id`）が入っていません**（機器名・真値などだけ）。点検結果は機器IDごとに集計するため、機器IDは、PCが**画像に写ったQRラベル**を読んで付けます（`manager/ingest.py`）。QRが写っていない写真は、「記録」タブには出ても、「点検結果」タブの対象機器には出ないことがあります。

### 手順
- [ ] PCのアプリで、タブ「**点検結果**」を開く
- [ ] 「点検ID」（既定は `INS-YYYYMMDD-HHMM`）、「開始日」「終了日」（既定は今日）、「対象機器」が出る
- [ ] 対象機器に、QRで読めた機器が入っている。写真を撮った日が範囲に入っている（日をまたぐなら終了日を広げる）。ファイル名の時刻はUTCなので、日付の境目の時間帯の撮影は注意する
- [ ] 表に、列「機器番号」「機器名」「測定値」「単位」「測定方法」「読取状態」「要確認理由」「撮影日時」で、届いた写真の行が出る
- [ ] 「書き出す」を押すと「保存しました:」と保存先のパスが出る（書き出しは任意。書き出すと、出力ファイルが増える）
- [ ] 比較用に、タブ「**記録**」でも同じ写真が見える

### 期待される結果
- [ ] 4・5章で送った写真が、「記録」タブに**1枚1件**で出る
- [ ] QRが読めた機器は、「点検結果」タブの表に出る

### 違ったときに見る場所
| 症状 | 見る場所 |
|---|---|
| 「機器が登録されていません。」 | 機器IDが1つも登録されていない。QRラベルが写った写真が取り込まれていない |
| 「期間内に対象機器の記録がありません。」 | 開始日・終了日、対象機器の選択 |
| 「期間内に撮影が無い機器: …」 | 警告。その機器の写真が範囲内にない |
| 「記録」タブにも出ない | `watch_inbox.py` のコンソール（`[パイプライン失敗]`、エラー情報）。`incoming/` に画像があるか |
| 写真は出るが機器名が `unknown` | 撮影時に機器名を入れたか。入れても機器IDがないと点検結果の集計には出ない |
| 点検結果の画面がエラー | 画面の「点検結果を作れません: …」の文言を記録欄に書く |
