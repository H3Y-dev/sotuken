# 精度改善: 針の両側の数字で読む（第一案）仕様

作成: 2026-10-21（Claude、大久保と合意した方針に基づく）
状態: 仕様確定前のレビュー待ち。実装は `codex-sol` に段階ごとに委任し、Claudeが実データで検証して、採否は大久保が決める。

## 1. 目的と背景

- 現行は、0点と満尺点（両端）を必須にして値を出している（`meter_pipeline.read_meter` → `meter_reader.compute_reading`）。両端のどちらかを取り違えると値全体が狂う。
- 唯一の許容外（気密試験_昇圧後、真値100.75、4.83%FS）では、OCRが「100」を「108」と誤読した。さらに150の目盛り線が検出できず、範囲を0〜108と判定した。今の低信頼判定（`scale_confident`）は、この「範囲の取り違え」を捕まえられない（9枚すべてTrue）。
- 人がメーターを読むときは、針を見て、針の両側の数字との位置関係で読む。これを処理に取り入れる。

方針（2026-10-21決定。詳細はObsidian `project-sotuken-team` の「方針見直しの結論」）:
1. 針の両側の数字で値を出す（局所方式）。
2. 現行方式（全体方式）は毎回並行して計算し、フォールバックと突き合わせに使う。
3. 誤読対策をE→B→C→Dの順に1つずつ足し、効果を分けて測る。
4. LLMは値の出どころにしない。検証役（選択式の質問）に限る。

## 2. 対象範囲

- 変更するファイル: `meter_pipeline.py`、`meter_reader.py`（針の角度と確からしさ）、新規 `local_reading.py`（局所方式の本体）、`evaluate.py`（出力項目とオプション）、`tests/`。
- 変更しないファイル: `tick_detect.py`、`scale_value_detect.py` の既存関数の振る舞い。呼び出して使うのはよいが、既存の戻り値と判定は変えない。必要な情報が取れない場合は、診断用の戻り値を追加するだけにとどめる。
- 対象は丸型（`--scope round`）。

## 3. 用語

- **数字付き目盛り**: OCRで読んだ数字を、目盛り線に対応付けたもの。角度θ（ラジアン、画像座標で中心から見た向き）、値v、OCRスコアs、合成フラグ（`synthetic`）を持つ。材料は `scale_value_detect` の `bind_numbers_to_ticks` の結果と、`calibration`（単調な並びとして残った点、`survivors`）。
- **走査方向**: 値が増える回転の向き（時計回り／反時計回り）。
- **括弧**: 針の角度θnを挟む、隣り合った2つの数字付き目盛り(A, B)。走査方向にA→針→Bの順に並ぶ。

## 4. 処理の流れ

```
中心（現行どおり）→ 目盛り（現行どおり）→ 数字（現行どおり）
  → 針（現行の detect_needle。中心だけあれば検出できる）
  → [局所方式] 括弧(A,B)を選ぶ → 誤読チェック（E→B→C→D、有効なものだけ）→ 値
  → [全体方式] 現行の compute_reading（変更なし）
  → 採用値の決定と突き合わせ
```

### 4.1 針（段階0で手当て）

- `detect_needle` の戻り値に、角度を「中心→針先」の向きで求めた `angle_tip` を追加する。今の `direction`（Hough線分の向き）はそのまま残す。
- 確からしさ `needle_confidence` を返す: 候補線の本数、最長候補と2番目の候補（別方向のもの）の長さの比、針先までのエッジの連続性。
- どちらの角度を値に使うかは、評価で決める（フラグで切り替え）。

### 4.2 括弧の選び方

1. 数字付き目盛りの候補を集める。`calibration`（`survivors`）を優先し、ない場合は対応付けの全点を使う。同じ値が複数あれば、OCRスコアの高い方を残す。
2. 走査方向を決める。角度の順に並べたとき、値が増えるのが時計回りか反時計回りかを、隣り合う点の多数決で決める。2点しかなくても決まる（値の大小と角度の向きから）。現行の目盛り角度による方向判定（`_resolve_cw`）は使わない。
3. 走査方向に沿って針の角度を挟む隣り合った2点を選び、A→Bとする。
4. 針が最初の数字より手前、または最後の数字より先にある場合は、局所方式は不成立とする（外挿しない）。その場合は全体方式を使う。
5. 針がちょうど数字の上にある場合（角度差が目盛り間隔の1/10未満）は、その数字と次の数字を括弧にする。

### 4.3 値の計算

```
v = vA + (vB − vA) × Δθ(A→針) / Δθ(A→B)   （Δθは走査方向に沿った角度差、0〜2πで正規化）
```

### 4.4 誤読チェック（段階ごとに足す。各チェックはフラグで個別にオン／オフできる）

チェックは、括弧の2点（A, B）とその隣の点の値を確かめる。結果は「合格」「修正」「不合格」のどれか。
- 修正：複数のチェックが一致して別の値を指した場合だけ、値を置き換える（例: 108→100）。数字の角度（位置）は動かさない。
- 不合格：局所方式を不成立にして、全体方式に回す。

| 段階 | 記号 | 内容 | 判定 |
|---|---|---|---|
| 2 | E | 切りのよさとOCRスコア | 候補の値の差から主目盛りの刻み（最頻値）を推定する。刻みの倍数でない値や、スコアが他より明らかに低い値（しきい値は評価で決める）を「疑わしい」とする |
| 3 | B | 小目盛りの本数 | 目盛りの通し番号（既存の `_arc_order` / `_tick_slots`）で、A→Bの間の本数と、他の隣り合う数字の間の本数を比べる。「本数÷値の差」が全体の周期（既存の `_fit_major_cadence`）と合わなければ「疑わしい」。合うように値を直した候補も出す（例: 50→「108」の本数が0→50と同じなら、その数字は100） |
| 4 | C | 読み方を変えて多数決 | A, Bの数字の位置を切り出し、文字を正立に回す・拡大率（2〜3通り）・CLAHE・2値化を変えて複数回OCRし、多数決を取る。局所OCRは既存の `_resolve_scale_position` の仕組みを使い回す |
| 5 | D | LLMに選択式で聞く | E/B/Cで食い違いが残ったときだけ呼ぶ（`use_vlm=True` のときのみ）。針の周りを切り出し、「針の左右の数字は次のどれか」を候補（OCRの値、B/Eで直した値）から選ばせる。Ollamaの `options` に `temperature: 0` と `seed`（固定値）を入れる。LLMの答えだけでは値を決めない。E/B/Cのどれかと一致した候補だけを採用する |

### 4.5 採用値の決定と突き合わせ

- 局所方式が成立 → 局所の値を採用する。成立しない → 全体方式の値（現行どおり）。
- 両方成立した場合は、差を引用誤差（%FS）で求める。範囲は全体方式の min/max、なければ局所の数字から推定した範囲を使う。差が**2.5%FS**（許容値と同じ。評価で見直す）を超えたら `scale_confident=False` にする。`manager/record.judge_status` では `low_confidence` になる。
- 全体方式が失敗した（`scale is None`）が局所方式が成立した場合は、値を返して `stage=ok`、`scale_confident=False` とする（今は失敗扱いになっている）。

### 4.6 戻り値に足す項目（`read_meter` の result）

- `value_local`, `value_global`, `read_method`（`'local'` / `'global'`）
- `cross_check_diff_fs`
- `bracket`: `{a:{value,angle,score,synthetic}, b:{...}}`
- `local_checks`: 各チェックの結果（`{E:'pass'|'fixed'|'fail'|'off', ...}`）と、直した値
- `needle_confidence`, `needle_angle_source`（`'segment'` / `'tip'`）

既存の項目（`value`, `ratio`, `min_value`, `max_value`, `zero_pt`, `full_pt` 等）の意味は変えない。`value` は採用値。

## 5. 切り替えと評価

- `read_meter(img, use_vlm=True, local_read=True, local_checks=('E','B','C','D'), needle_angle='segment')` のように引数で切り替える。既定値は、段階ごとの評価で採用が決まるまで**現行と同じ結果になる設定**（`local_read=False`）にしておく。
- `evaluate.py` に `--local-read` と `--local-checks E,B,C,D` と `--needle-angle tip` を足す。行ごとに `read_method`、`value_local`、`value_global`、`cross_check_diff_fs`、`local_checks` を出し、集計に「局所方式の成立率」「突き合わせで要確認になった件数」を足す。
- 評価は、AIなし（`--no-vlm`）とAIありを分けて出す。

## 6. 段階と受け入れ条件

各段階は別々のPRにする。PRには、評価結果（丸型9枚、AIなし）と、前の段階との比較表を付ける。

| 段階 | 内容 | 受け入れ条件 |
|---|---|---|
| 0 | 針の `angle_tip` と `needle_confidence` を追加（使うかはフラグ） | 既定設定で9枚の結果が完全に同じ。テスト追加 |
| 1 | 局所方式＋フォールバック＋突き合わせ（チェックなし） | 既定設定で結果が同じ。`--local-read` で、許容内が8/9以上、平均が1.37%FS以下、破滅0。気密試験_昇圧後が要確認に入るかを報告 |
| 2 | E | 段階1から悪化しない。気密試験_昇圧後の108が「疑わしい」になるか |
| 3 | B | 同上。108→100に直せるか |
| 4 | C | 同上。処理時間の増加を報告 |
| 5 | D | AIありで評価。AIなしの結果は段階4と同じであること |

- 共通: 既存のテストがすべて通ること（2026-10-21時点で215件）。新しいテストは、角度と値を手で与えた合成の数字付き目盛りで、括弧の選択・走査方向・針が範囲外・針が数字の上・各チェックの判定を確かめる。
- 9枚では差がまぐれと区別できないので、最終判断は画像収集（丸型6台以上×2〜3値×5条件）と工程ごとの正解がそろってから行う。それまでは「悪化しないこと」と「既知の失敗例での挙動」だけを見る。
- 計器台帳（A）が不要と判断する基準: 拡充した評価セットで、最終値の計算に誤読数字が使われた件数0、かつ許容外の割合が現状（1/9）以下。
