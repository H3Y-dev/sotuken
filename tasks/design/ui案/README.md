# Android 点検フローの画面案

[案A：大きな操作](案A.html) ／ [案B：進み具合](案B.html) ／ [案C：現行画面の延長](案C.html)

HTMLをブラウザで直接開いてください。各ファイルに同じ範囲の画面を縦に並べています。画面幅は最大390pxで、360〜412pxのスマホでも収まる構成です。CSSは埋め込みで、外部のフォント・画像・通信は使いません。写真とカメラ映像は灰色の代用表示です。

これは画面比較用の静的モックです。リンクは関連する画面例へ移動します。入力値の保存、QRの読み取り、撮影、削除、送信は動作しません。表示している点検名・担当者・機器・時刻・接続状態はサンプルです。

## 共通の流れ

1. 点検を作り、担当者と場所を入力する。点検名は日付からの自動名を初期表示する。
2. 機器ラベルのQRを読むか、機器名・機器IDを手入力する。
3. 写真と機器名・機器ID・撮影時刻を一緒に保存する。点検内の履歴で写真ごとに確認し、撮り直し・削除へ進む。
4. 写真の枚数、撮影済みの機器数、未撮影・重複の注意を確認し、点検を完了する。
5. 完了した点検は送信待ちとなり、PCに届く接続を確認したら自動で送信する。
6. 写真と写真一覧の両方がPCに届いたら送信済みと表示する。一部失敗では失敗した写真だけ再送する。

状態は「作業中 → 送信待ち → 送信中 → 送信済み」です。一部失敗は「送信済み（一部失敗あり）」と表示し、未到着の枚数を明記しています。

各案には一覧・作成・撮影・点検内の履歴・完了確認・送信待ち・送信中・送信済み・一部失敗・未接続時の案内があります。補足として、機器QR、手入力、撮影直後、削除確認、既存の送信先設定への導線も示しています。

## サンプルの読み方

基本の点検は「11/06 朝の点検」で、写真3枚・撮影済み2機器です。A-101を2枚、A-102を1枚撮影し、対象一覧がある場合はA-103が未撮影です。送信中は2 / 3枚が到着、一部失敗はA-102の1枚が未到着という同じ記録を使っています。

「03c 撮影直後」だけはA-103を撮った後の別の時点で、写真4枚・3機器です。それ以降の画面例は基本の写真3枚・2機器に戻ります。ボタンを押しても表示データが更新されるわけではありません。

対象一覧がない場合は、全案とも写真の枚数と撮影済み機器数を表示し、未撮影は判定できないことを伝えます。Bでは対象数を分母にする進捗表示と未撮影リストを省き、写真の履歴を中心にします。

## 接続と送信の表示

全画面に接続の種類とPCへの到達状況を表示します。Wi-Fiに接続していてもPCに届かない状態と、未接続の状態を分けています。USBテザリングを有効にする操作はスマホの設定で行い、アプリは接続状況を表示します。接続なしの案内は「USBでPCにつなぐ → スマホの設定でUSBテザリングをオン → PCの受信アプリを開き、到達表示を確認」の3手順です。

送信単位は画面上では点検です。内部では写真1枚ずつに点検IDを付け、最後に写真一覧（manifest）を小さなJSONで送ります。zipにはしません。画面には実装用語を出さず「写真の一覧」と表示します。写真だけ届いても送信済みにはせず、一覧の到着も確認します。一覧だけが失敗した場合は一覧だけ再送する別の例を載せています。

機器QRは機器名・機器IDの入力用です。現行のPairingScreenで使う「送信先QR」はPCの登録用で、用途を分けています。送信先の手入力設定は現行の仕組みを使う想定です。

## 共通して決めること

| 項目 | 決める内容 | 画面案での仮置き |
| --- | --- | --- |
| 対象機器の事前登録 | 登録するか、どこで管理するか、スマホへどう渡すか | 登録済みの3機器を例示。登録がなければ未撮影判定と総数の表示を省く。登録画面は作っていない |
| 撮り直し | 元の写真を置き換えるか、別の写真として追加するか | 履歴の「撮り直す」から同じ機器名・IDを引き継いだ撮影画面へ進む。元の写真を残すかは未決定。重複は警告のみ |
| 点検名の自動採番 | 日付の書式、同日に複数回作る場合の連番、変更の可否 | 「11/06 朝の点検」を表示例に使用。採番規則は未決定。画面上の名前と送信用の点検IDは区別する |
| 入力の必須項目 | 担当者・場所・機器名・機器IDをどこまで必須にするか | 入力欄を示すだけで、必須・任意の規則は確定していない |
| 未撮影・重複がある点検の完了 | 完了を止めるか、注意を確認したうえで許可するか | 注意を表示し「確認して点検を完了する」で進める仮案 |
| 完了後の修正 | 再開を認めるか、送信中・送信済みの変更をどう扱うか | 完了後の撮影・削除は置いていない。再開の可否は未決定 |
| 再送の扱い | 自動再試行の回数・間隔、写真一覧の到着確認 | 失敗した写真だけの手動再送と、一覧だけの再送を例示。再試行規則は未決定 |

## 現行画面との対応

- `MeterCaptureApp.kt`：撮影と履歴の切り替えを確認。Cはこの構成を生かし、点検の一覧を入口に加える。
- `QueueListScreen.kt`：写真単位のカード、送信状態、再送・削除の操作を確認。点検の履歴と送信結果に同じ考え方を使う。
- `QueueDisplay.kt`：機器名・時刻・状態の表示を確認。各写真に機器IDも併記し、点検ごとの集計を加える。
- `PairingScreen.kt`：PC登録用QRの導線を確認。機器ラベルのQRと文言を分ける。

Kotlin・既存アプリのコードは変更していません。

## 確認したこと

3案ともブラウザでファイルを直接開き、幅360px・390px・412pxで確認しました。各19画面の横のはみ出し、画面内リンクの切れ、外部への読み込みは0件でした。Aの撮影、Bの履歴、Cの撮影はスクリーンショットでも表示を確認しています。撮り直しは選んだ機器名・ID、削除は選んだ写真・撮影時刻が表示される画面例へ移動します。

日本語の画面文言と本文はyomiyasuで検査し、依頼内容と照合しました。架空の数値・機器名はサンプルとして明記しています。実機での操作、手袋での反応、QR読み取り、撮影、保存、通信、Androidのビルドは未確認です。
