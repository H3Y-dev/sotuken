# label_tool.py 拡張: 工程ごとの正解を保存する（担当: SRくん）

作成: 2026-10-21（Claude）。方針はObsidian `project-sotuken-team` の「方針見直しの結論（2026-10-21）」。

## 1. なぜやるか

今の評価は最終的な値しか正解を持っていない。そのため外れたときに、中心・目盛り・数字・針のどこで外れたのかが分からない。
`label_tool.py` は今も4点（中心・0点・満尺点・針先）をクリックさせているが、クリックした座標を保存していない。
これを保存できるようにし、さらに数字付きの目盛りも記録できるようにする。

## 2. 変えること（`label_tool.py` だけ。他のファイルは触らない）

### 2.1 今の4点はそのまま

`STEPS`（中心 → 0点 → 満尺点 → 針先）と真値の計算（`meter_reader.arc_ratio` / `ratio_to_value`）は変えない。

### 2.2 5つ目の手順「数字付きの目盛り」を追加

- 4点のあとに、「数字が書いてある目盛りの線を順にクリックし、その数字を入力してください。終わったら『数字の入力を終える』を押してください」と案内する。
- クリックするたびに値を入力するダイアログ（`simpledialog.askfloat`）を出す。キャンセルしたらその点は取り消す。
- 数字の文字の上ではなく、その数字に対応する**目盛りの線の真ん中**をクリックする（案内文に書く）。
- 0点と満尺点の目盛りも、ここでもう一度クリックしてよい（重複してもかまわない）。
- 「1つ戻す」ボタンで最後の点を消せる（今の `undo_point` と同じ考え方）。

### 2.3 入力欄を追加（画面右側）

| 項目 | 形 | 既定値 |
|---|---|---|
| 担当者名 | 文字（例: SR） | 空。空のままでは保存できない |
| 機器番号 | 文字（例: A-101、学校の計器は自分で付けた名前） | 空 |
| 撮影条件 | 選択: 正面 / ブレ / 斜め30 / 斜め45 / 反射 | 正面 |
| 形 | 選択: round / square / fan | round |
| 単位 | 文字（例: MPa、℃） | 空 |
| 主目盛りの刻み | 数値（例: 50） | 空 |
| 目で読んだ値 | 数値（任意） | 空 |
| 付けられない | チェック（ブレや反射で自信が持てないとき） | オフ |

### 2.4 拡大表示

クリック位置の精度が大事なので、マウスの周り（例: 60×60ピクセル）を4倍に拡大した小窓を、画面の隅に表示する。中心に十字を描く。

### 2.5 保存先: 担当者ごとのファイル

- ボタン「ラベルを保存」で、`eval/labels/<担当者名>.json` に保存する。人ごとにファイルを分けるのは、2人が同じ画像に付けてもgitで競合しないようにするため。
- ファイルの中身は配列で、同じ画像を付け直したら上書き確認のうえで置き換える。
- 今の「groundtruth.jsonに追記」ボタンは残す（動きは変えない）。

1件の形:

### 2.6 保存の形を作る処理は関数に分ける

画面に依存しない関数 `build_label_record(image_path, image_size, points, numbered_ticks, form, computed)` を作り、上の辞書を返すようにする。テストはこの関数に対して書く。

## 3. テスト
