# 目盛りの等間隔格子を延長して、端の数字を拾う

作成: 2026-08-26 ／ 設計: 本人 ／ 実装: Codexへ委任
前提: `tasks/design/主目盛り判定の再設計.md` の実装が完了していること

## 何が問題か

**OCRは数字を正しく読めているのに、その位置に目盛り線が検出されていないという
理由だけで、その数字を捨てている。**

決定的測定（`--no-vlm`、VLMを完全に切った状態）での実測:

| 画像 | 捨てられた数字 | その数字と最寄り目盛りの角度差 |
|---|---|---|
| 気密試験_昇圧前圧力計 | **150** | 52.4° |
| 20260817_134745 | **0** | 21.9° |
| meter2 | **0** と **100** | 13.5° / 39.0° |

対応付けの許容角度は12°なので、いずれもそれを超えて棄却される。
結果、検出範囲がこうなる。

| 画像 | 検出 | 真値 |
|---|---|---|
| 気密試験_昇圧前 | 0〜100 | 0〜150 |
| 20260817_134745 | 20〜100 | 0〜100 |
| meter2 | 10〜90 | 0〜100 |

現状の成績（round、9枚、決定的測定）:

```
読取成功 9/9   許容内 5/9   平均 5.82 %FS   中央値 1.47 %FS   破滅的失敗 0件
範囲一致 2/9
```

## なぜ今なら解けるのか

主目盛り判定の再設計で、**目盛りが等間隔の格子に乗っていることと、値と格子位置が
1本の直線に乗ることが、すでに求まっている。**

- `_tick_slots` … 円弧に沿った通し番号（欠けていても正しく数えられる）
- `_fit_major_cadence` … 値と通し番号を結ぶ直線（傾き・切片）、周期、位相

**格子は検出できた目盛りの範囲の外にも、そのまま延長できる。**
角度は `先頭の目盛りの角度 + 通し番号 × 刻み幅` で決まる。
目盛り線が写っていなくても（針に隠れていても、検出に失敗していても）、
**その値があるべき座標は計算で出せる。**

## 変更内容

### 1. 格子モデルを取り出せるようにする

いまは `refine_major_ticks_from_numbers` の中で求めて捨てている。
これを関数に切り出し、モデルを返すようにする。

```python
def build_tick_grid(numbers, ticks, center, max_angle_deg=12.0):
    """目盛りの等間隔格子と、値との対応（直線）を求める。

    戻り値: dict または求められなければ None
        cadence     … 主目盛りが副目盛り何本ごとに現れるか
        phase       … 主目盛りが乗る通し番号の余り（通し番号 % cadence）
        slope       … 値1あたり通し番号がいくつ進むか
        intercept   … 値0のときの通し番号
        period      … 目盛り1本あたりの角度（ラジアン）
        base_angle  … 通し番号0の目盛りの角度（ラジアン）
        min_slot    … 検出できた目盛りの通し番号の最小
        max_slot    … 同じく最大
        radius      … 目盛りの中心からの距離の中央値
    """
```

`refine_major_ticks_from_numbers` はこれを呼んで `is_major` を付け直す形に直す。
**外から見た振る舞いは変えない**（既存の呼び出し側・テストが通ること）。

### 2. 格子の外にある数字のために、目盛りを合成する

```python
def extend_ticks_to_numbers(numbers, ticks, center, max_angle_deg=12.0):
    """検出できていない位置の主目盛りを、格子から計算して補った目盛り一覧を返す。"""
```

手順:

1. `build_tick_grid` でモデルを得る。得られなければ `ticks` をそのまま返す。
2. 既存の目盛りに `max_angle_deg` 以内で対応付く数字を求める（`_bind_number_tick_indices`）。
   **対応付いた数字は対象外。**
3. 残った数字それぞれについて:
   1. `predicted = slope * value + intercept`
   2. **格子に吸着させる**: `predicted` に最も近い整数 `s` で `s % cadence == phase`
      を満たすものを選ぶ
   3. `abs(s - predicted) > cadence * 0.75` なら**捨てる**（どの主目盛りか決められない）
   4. 角度 `angle = base_angle + s * period`
   5. **その数字自身の角度と `angle` の差が `max_angle_deg` を超えるなら捨てる。**
      これが最重要の安全弁。「格子がそこにあると言っている」だけでなく
      「実際にその数字がそこに印字されている」ことを要求する
   6. `s` が `[min_slot - cadence*2, max_slot + cadence*2]` の外なら捨てる
      （外挿の暴走よけ）
   7. 合成した目盛りを追加する:
      ```python
      {'angle': angle,
       'centroid': (cx + radius*cos(angle), cy + radius*sin(angle)),
       'line_angle': angle,
       'length': 0.0,
       'is_major': True,
       'synthetic': True}
      ```
4. 角度順に並べ替えて返す。

`synthetic` を付けておくのは、**描画で実測点と区別できるようにするため**。
これが無いと、目視検証で「検出できた点」と「計算で置いた点」の区別がつかない。

### 3. パイプラインに組み込む

`_run_ocr_tick` の中で、`refine_major_ticks_from_numbers` の直後に
`extend_ticks_to_numbers` を呼ぶ。以降の `bind_numbers_to_ticks` /
`determine_min_max` は変更不要（合成された目盛りに数字が対応付くようになる）。

### 4. 描画で区別できるようにする

`tools_render_overlays.py` で、`t.get('synthetic')` が真の目盛りは
**マゼンタの塗りつぶし丸ではなく、マゼンタの輪郭だけの丸**で描く。
凡例（モジュール先頭のdocstring）にも1行足す。

### 期待する変化

範囲一致が **2/9 → 6/9** になること。内訳:

| 画像 | 現在 | 期待 |
|---|---|---|
| 気密試験_昇圧前 | 0〜100 | 0〜150 |
| 気密試験_昇圧後 | 0〜108 | 0〜150（108はOCRの誤読なので直らない可能性あり） |
| 20260817_134745 | 20〜100 | 0〜100 |
| meter2 | 10〜90 | 0〜100 |

**直らないもの**（この設計の対象外）:

- 耐圧試験_昇圧前/後 … OCRが `0` を**読めていない**（読めた数字は100/200/300/400のみ）。
  格子は延長できるが、延長先に置くべき値が分からない。別途対策が要る
- 20260817_134647 … OCRの誤読（90度回転。`0`→`2`、`100`→`111`）。T3の領域

### 悪化していないことの確認

- `読取成功` が 9/9 のまま
- `破滅的失敗(25%FS超)` が 0 件のまま
- **`許容内` と `平均` が悪化していないこと。** 悪化していたら、合成した目盛りが
  誤った位置に入っている

### 目視で見るところ

`eval/overlays/` の9枚を開き、**輪郭だけのマゼンタ丸（合成した主目盛り）が、
実際の目盛り線の上に乗っているか**を確認する。盤面外・数字の上・
隣の目盛りにずれていたら失敗。
