# 卒研チーム Git/GitHub 運用マニュアル

このファイルは「作業のたびに何をするか」をまとめた手順書です。**開発未経験でも
分かるように書いてあります。** 分からない箇所があれば、このファイルの内容を
まるごと自分が使っているAI（Claude/Gemini）に貼り付けて、「この手順通りに
一緒にやってほしい」と頼んでください。

関連ファイル:
- 作業を終えてPRを出すときの詳しい手順 → `tasks/GitHub共有手順.md`
- タスクの受け入れ条件 → `tasks/todo.md`

## 0. なぜこのルールが必要か

2026-08-24、実際に次の問題が起きました。

- あるメンバーの作業が、評価の仕組み等が追加される**前の**古いmainから
  分岐したまま数日放置されており、もしそのままマージしていたら直近の
  作業が丸ごと消えるところだった
- メンバーごとにPythonのバージョンが揃っておらず、片方の環境では動くのに
  もう片方では動かないコードが生まれかけた
- ライブラリの依存関係が競合し、原因不明のエラーになる環境があった

**これらは全員が同じ手順を踏めば防げる問題です。** そのためのルールです。

## 1. 作業を始める前に毎回行うこと

作業を始めるたびに、以下の順番で実行してください。**「昨日と同じ状態のはず」と
思い込まず、毎回確認する**のが事故を防ぐコツです。

### ステップ1: 仮想環境（venv）を有効化する

```powershell
.\venv\Scripts\Activate.ps1
```

ターミナルの先頭に`(venv)`と表示されればOKです。表示されない場合、
別のPythonにライブラリをインストールしてしまい、あとで
`ModuleNotFoundError`になります。

### ステップ2: 今の状態を確認する

```powershell
git status
```

**「Changes not staged」や「Untracked files」に見覚えのないものが無いか確認してください。** 前回の作業の続きなら問題ありません。

### ステップ3: 最新のmainを取り込む

```powershell
git fetch origin
git rebase origin/main
```

もし未コミットの変更が残っていて`rebase`が失敗する場合は、先に退避します。

```powershell
git stash              # 今の変更を一旦どこかへ避難させる
git rebase origin/main # 改めて最新を取り込む
git stash pop          # 避難させた変更を戻す
```

`stash`の詳しい説明: 「棚上げ」のイメージです。作業を一旦きれいな状態に戻して、
安全に`pull`/`rebase`できるようにし、終わったら`pop`で元に戻します。

### ステップ4: 動作確認

```powershell
python -m unittest discover -s tests
```

**作業を始める前にこれを実行し、全部通ることを確認してください。** ここで
既に失敗していたら、それは自分の変更のせいではなく、環境か最新mainの
どちらかに問題があるということです。始める前に気づけると原因の切り分けが
楽になります。

## 2. ブランチの運用ルール

- **1つの作業テーマにつき1つのブランチ**を作る。複数の作業を1つのブランチに
  混ぜない
- ブランチ名は「担当＋内容」が分かる形にする（例: `feature/t1-2-circle-fit`）
- **同じブランチで何日も作業を続けない。** 最低でも1日の作業開始時（上記1章）
  には必ず最新mainを取り込む
- 作業が一区切りついたら、完成していなくてもこまめにpushしてよい
  （下書き状態のPRとして「Draft」を選べます。完成したら通常のPRに切り替えられます）

## 3. 環境を揃えるための注意点

チームで環境差によるトラブルが実際に起きたため、特に重要な4点です。

### Pythonのバージョンを必ず3.8系にする

このPCの環境によっては、`python`コマンドが3.8以外（3.11や3.14等）を指して
いることがあります。venvを作るときは必ずバージョンを指定してください。

```powershell
py -0                 # インストール済みのバージョン一覧を確認
py -3.8 -m venv venv  # 3.8を明示的に指定してvenvを作る
```

### opencv-python と opencv-contrib-python を同時に入れない

`pip install -r requirements.txt`を実行すると、依存関係の都合で
`opencv-python`が余分にインストールされてしまうことがあります。
**これが入っていると、`cv2`の挙動がおかしくなり、原因不明のエラー
（`cannot unpack non-iterable numpy.int32 object`等）が出ます。**
インストール後に必ず次の2行を実行してください。

```powershell
python -m pip uninstall -y opencv-python
python -m pip install --force-reinstall --no-deps opencv-contrib-python==4.10.0.84
```

### `print()`に絵文字を使わない

日本語Windowsの標準の文字コード（cp932）では絵文字を画面に出せず、
プログラムが途中で止まります（`UnicodeEncodeError`）。日本語の文章自体は
問題ありません。絵文字だけが原因です。`[OK]` `[NG]` `[結果]`のような
普通の文字を使ってください（詳細は`tasks/GitHub共有手順.md`参照）。

### 画像パスの読み込みは`cv2.imread`ではなく専用の書き方を使う

日本語（全角文字）を含むパスがあると`cv2.imread`は失敗して`None`を
返すことがあります。このプロジェクトでは次の書き方で統一しています。

```python
img = cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)
```

## 4. 作業が終わったら

コミット→push→PR作成の詳しい手順は `tasks/GitHub共有手順.md` を見てください。
要点だけ書くと:

```powershell
git add <変更したファイル>
git commit -m "何をしたか一言"
git push -u origin <ブランチ名>
```

pushすると表示されるリンクをブラウザで開き、「Create pull request」を押せば
完了です。以降のレビュー・マージは本人（大久保）が行います。

## 5. 絶対にやってはいけないこと

以下は**データが消える可能性があるコマンド**です。実行前に必ずAIか
本人（大久保）に確認してください。

| コマンド | 何が起きるか |
|---|---|
| `git reset --hard` | 未コミットの変更が全て消える |
| `git push --force` | リモート（GitHub）側の履歴を上書きし、他人の作業が消える可能性がある |
| `git branch -D <ブランチ名>` | ブランチとその中の未マージの変更が消える |
| `git checkout .` / `git restore .` | 未コミットの変更が全て消える |

**「よく分からないけどこれで直りそう」という理由で上記を実行しない。**
分からない状態のときほど、まず`git status`の結果をAIに見せて相談してください。

## 6. 毎回のチェックリスト

**作業前**
- [ ] venvを有効化した（プロンプトに`(venv)`が出ている）
- [ ] `git status`で今の状態を確認した
- [ ] `git fetch origin && git rebase origin/main`で最新を取り込んだ
- [ ] `python -m unittest discover -s tests`が通ることを確認した

**作業後**
- [ ] `git status`で変更内容を確認した（余計なファイルが混ざっていないか）
- [ ] コミットメッセージに何をしたか書いた
- [ ] pushしてPRを作った
- [ ] Slackで一言連絡した
