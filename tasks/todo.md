# タスク一覧

各タスクは「単独で着手でき、単独で合否を判定できる」単位に切ってある。
合否はすべて評価基盤（`evaluate.py`）の数値で判定する。

```bash
venv\Scripts\python.exe evaluate.py eval/groundtruth.json -o eval/report.json
venv\Scripts\python.exe -m unittest discover -s tests
```

**全タスク共通の完了条件**
- [ ] `python -m unittest discover -s tests` が通る（過去ログ24件の回帰テストを含む）
- [ ] 評価基盤で改善前後の数値を記録し、悪化していないことを示す

## Phase 0: 着手前に必要（他の全タスクの前提）

### T0-1: 真値ラベルの記入
**内容:** `eval/groundtruth.json` の `true_value` を埋める。
**受け入れ条件:**
- [ ] 丸型温度計3枚と角形メーター2枚以上に真値が入っている
- [ ] 目盛り線を数えて読む（非線形スケールのため角度按分では読まない）
- [ ] 自信のない画像は `null` のまま残す（誤ラベルは無ラベルより有害）

**検証:** `evaluate.py` が実行でき、母数が0でなくなる
**依存:** なし　**規模:** S　**担当:** 本人

### T0-2: インターフェース3点の確定
**内容:** `tasks/plan.md` の「先に決めるインターフェース」をチームで合意する。
**受け入れ条件:**
- [ ] 中心推定・目盛り較正点・読み取り結果の3つの型が確定している
- [ ] 各トラックの担当ファイルが決まり、重複がない

**依存:** なし　**規模:** XS　**担当:** 全員（30分の打ち合わせ）

### T0-3: 撮影データの追加
**内容:** 評価用の写真を追加する。13枚では条件が偏っている。
**受け入れ条件:**
- [ ] 同じメーターを距離・角度・明るさを変えて撮った組がある
- [ ] 正対した写真（回転なし）も含める（回転の影響を切り分けるため）
- [ ] 30枚以上

**依存:** なし　**規模:** M　**担当:** 本人（現場アクセスが必要）

## Phase 1: 精度の土台（並行実施可）

### T1-1: 目盛り線の交点から中心を推定する（中心が画像外でも可）
**内容:** 目盛り線は必ず中心を向くという幾何を使い、線の交点を最小二乗＋RANSACで
求める。現行の「中心は画像内」制約を撤廃し、盤面外の中心も返せるようにする。
**受け入れ条件:**
- [ ] `estimate_center(img, ticks)` が画像外の座標を返せる
- [ ] 外れ値（針・文字・ネジ）が混ざっても中心が大きくずれない
- [ ] 角形メーター5枚で、推定中心が針の回転軸付近（目視確認）にある

**検証:** 単体テスト（既知の中心から目盛り線を人工生成して復元できること）＋評価基盤
**依存:** T0-2　**規模:** M　**ファイル:** `center_estimate.py`(新規), `tests/test_center_estimate.py`

### T1-2: 中心候補の検証と選択
**内容:** Hough円検出の結果と T1-1 の結果を突き合わせ、どちらが正しいかを
根拠を持って選ぶ。現行は「3%以上ずれたら目盛り側」という単純な閾値のみ。
**受け入れ条件:**
- [ ] 目盛り重心群への円フィッティングで整合性を検証している
- [ ] ネジを中心と誤検出した場合に棄却できる
- [ ] 丸型メーターで従来の正解が維持される（退行なし）

**検証:** 回帰テスト24件が通る＋評価基盤で引用誤差が改善
**依存:** T1-1　**規模:** M　**ファイル:** `center_estimate.py`, `meter_pipeline.py`(接続1行)

### T2-1: 目盛り全点を使った単調補間
**内容:** 両端2点の線形補間をやめ、OCRで値が対応付いた目盛りを全部使って
角度→値の単調な補間関数を作る。可動鉄片形の非線形スケールに対応する。
**受け入れ条件:**
- [ ] `value_from_angle(theta, calibration)` が2点以上の較正点で動く
- [ ] 較正点が2点のときは現行の線形補間と完全に一致する（回帰テストで担保）
- [ ] 較正点が単調でない場合（OCR誤読）に破綻せず、外れ値を除去する

**検証:** 単体テスト（非線形な人工スケールを与えて誤差が線形補間より小さいこと）
**依存:** T0-2　**規模:** M　**ファイル:** `meter_reader.py`, `tests/test_meter_reader.py`

### T3-1: 画像の向きを自動判定して正規化
**内容:** 90度回転した写真で目盛り数字が横倒しになりOCRが読めない問題を解く。
4方向を試してOCRの読み取り数が最大の向きを採用する等。
**受け入れ条件:**
- [ ] 回転した写真でOCRが読める数字の個数が増える（数値で示す）
- [ ] 正対した写真で退行しない
- [ ] 判定にかかる時間が許容範囲（OCR4回分が重ければ軽量な判定を検討）

**検証:** 回転前後でOCR結果を比較するテスト＋評価基盤
**依存:** T0-2　**規模:** M　**ファイル:** `orientation.py`(新規), `tests/test_orientation.py`

### チェックポイント: Phase 1完了時
- [ ] 角形メーターで中心が正しく取れている
- [ ] 評価基盤の引用誤差が改善している（改善前後の数値を記録）
- [ ] 回帰テスト24件が通っている
- [ ] ここまでの結果を卒論の実験結果として書ける形にまとめる

## Phase 2: 対応範囲の拡大（並行実施可）

### T4-1: 1枚の画像から複数のメーター盤面を検出する
**内容:** 現在は1画像1メーター前提。工場では1枚にパネル一面が写るのが実態。
**受け入れ条件:**
- [ ] 引き画像3枚から、写っているメーターの個数と位置を検出できる
- [ ] 銘板・ラベルをメーターと誤検出しない

**検証:** 検出数が正解と一致すること
**依存:** T0-2　**規模:** M　**ファイル:** `meter_locate.py`(新規)

### T4-2: 複数メーターを個別に読む
**内容:** T4-1の結果を使い、各盤面を切り出して個別に読む。
盤面内に限定することで銘板テキストのOCR混入も同時に解決する。
**受け入れ条件:**
- [ ] `read_meters(img)` が結果 dict のリストを返す
- [ ] 既存の `read_meter()` は変更せず残す（評価基盤とGUIが依存）
- [ ] 評価基盤が複数メーター画像を扱える（正解ファイルの形式拡張）

**依存:** T4-1　**規模:** M　**ファイル:** `meter_pipeline.py`, `evaluate.py`

### T5-1: 明暗が反転した盤面への対応
**内容:** 扇形メーターは暗背景に白目盛り。現行の二値化・輪郭抽出は
明背景に暗目盛りを前提にしている。
**受け入れ条件:**
- [ ] 盤面の明暗を自動判定し、反転した場合も目盛りを検出できる
- [ ] 白背景のメーターで退行しない

**依存:** T0-2　**規模:** S　**ファイル:** `tick_detect.py`

### T5-2: 指示針と設定針の区別
**内容:** 扇形メーターには白い指示針と赤い設定針がある。赤針を読むと常に誤答する。
**受け入れ条件:**
- [ ] 色情報を使って指示針を特定できる
- [ ] 針が1本のメーターで退行しない

**依存:** T5-1　**規模:** S　**ファイル:** `needle_detect.py`(新規)
